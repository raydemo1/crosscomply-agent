# CrossComply 统一界面设计规范

> 版本：2.0
>
> 状态：当前生效
>
> 适用范围：`frontend/src` 下所有案件工作台、审查报告、法源核查、整改、用户管理、模板中心和知识库页面。

这份文档是 CrossComply 后续页面和设计文档的基准。新增页面先遵守本文件；当某个页面确实需要独特布局时，再创建 `frontend/design/pages/<page-name>.md`，并在页面文档中明确覆盖项。没有页面级文档时，不得自行发明第二套颜色、字号、圆角或间距体系。

## 1. 产品视觉方向

### 1.1 核心概念

CrossComply 是“证据优先的合规工作台”，不是营销型数据大屏。界面应让用户快速回答三件事：

1. 当前案件处于什么阶段，谁需要下一步处理；
2. 结论依据哪些事实和法源，哪些内容仍不确定；
3. 用户可以执行什么动作，以及动作会留下什么审计痕迹。

### 1.2 视觉关键词

`克制、可信、编辑感、可审计、易阅读、渐进披露`

设计应接近一份结构清晰的法律审查工作台：标题有层级，正文有舒适的阅读宽度，风险和证据有明确但不过度的强调，装饰只服务于判断。

### 1.3 不可违背的原则

- 先层级，后装饰：页面标题、案件状态、风险结论和下一步动作必须一眼可见。
- 先阅读，后容器：长篇报告使用直接文字流，不把每个段落包成独立卡片。
- 先证据，后结论：法源、事实、缺口和引用关系必须可追溯，不能只显示一个“AI 结论”。
- 统一但不僵化：复用 token 和组件；只有语义不同才创建新组件或新变体。
- 低噪音：不使用渐变、发光、装饰性蓝色顶边或无意义的阴影叠加。

## 2. 页面骨架与宽度

### 2.1 应用外壳

| 区域 | 桌面规则 | 移动规则 |
|---|---|---|
| 左侧导航 | 256px，白色表面，右侧 1px 分隔线；桌面端随视口保持可用 | 隐藏，使用紧凑的移动页头 |
| 主工作区 | `flex: 1`，最小高度撑满视口，默认内边距 32px | 内边距 16px |
| 页面标题 | 在主工作区顶部统一对齐，使用 `.page-title` 或页面级标题样式 | 保持单行优先，必要时自然换行 |
| 页面内容 | 默认最大宽度 1120px；长篇报告整体不超过 1180px | 宽度 100%，不产生横向滚动 |

主工作区不能因为内容很长而整体 `position: fixed`。左侧导航可以 `position: sticky`，但正文、进度条、报告卡片和证据列表必须随页面正常滚动。

### 2.2 可读宽度

- 报告正文的实际阅读列控制在约 720–860px；不要让长段落铺满 1180px。
- 1180px 只用于“报告正文 + 证据入口/操作区”的整体布局，不代表正文必须占满。
- 中文普通段落建议每行 28–40 个汉字；英文或代码使用独立的可横向滚动区域。
- 页面左右留白优先于继续扩大文字列。遇到宽屏，增加留白，不增加段落行长。
- 页面级卡片只承载一个清晰的任务或信息组；卡片之间使用 16–24px 间距。

### 2.3 页头与吸顶

- 只有页面页头可以按页面需要吸顶；吸顶时必须有明确的背景、边界和 `z-index`，避免正文穿透。
- 案件进度、报告正文、法源核查列表、整改内容不吸顶，随页面一起滚动。
- 页头操作按“返回/标题/状态/主要动作”排序；次要动作收进“更多”，不要让按钮横向撑满。
- 页头和正文使用同一内容起始线，禁止页头过宽而正文过窄或反过来。

## 3. 设计 token

所有颜色、间距、圆角、阴影和动效优先使用 `frontend/src/styles/global.css` 中的 CSS 变量。页面 CSS 不得重复写一套近似值。

### 3.1 颜色

| 语义 | Token | 值 | 用途 |
|---|---|---|---|
| 权威蓝 | `--color-primary` | `#1e3a8a` | 主导航、链接、主要结构强调 |
| 深蓝 | `--color-secondary` | `#1e40af` | 链接 hover、次级强调 |
| 信任金 | `--color-accent` | `#b45309` | CTA、审批动作、提示性强调 |
| 页面背景 | `--color-background` | `#f8fafc` | 应用画布 |
| 表面 | `--color-surface` | `#ffffff` | 卡片、面板、输入区域 |
| 主文字 | `--color-foreground` | `#0f172a` | 标题和正文 |
| 次文字 | `--color-muted-foreground` | `#64748b` | 辅助说明、时间、元数据 |
| 边界 | `--color-border` | `#cbd5e1` | 1px 分隔线和输入边框 |
| 成功 | `--color-success` | `#047857` | 完成、通过、低风险 |
| 警告 | `--color-warning` | `#b45309` | 中风险、待补证、审批提醒 |
| 危险 | `--color-danger` / `--color-destructive` | `#b91c1c` / `#dc2626` | 高风险、失败、破坏性操作 |

风险颜色必须同时配合文字标签或图形状态，不能只依赖颜色区分。背景色使用低透明度 tint，正文使用对应深色文字，确保普通文字至少达到 WCAG AA 4.5:1 对比度。

### 3.2 字体

```css
--font-heading: 'Source Serif 4', 'Noto Serif SC', 'Songti SC', SimSun, Georgia, serif;
--font-legal: 'Noto Serif SC', 'Source Serif 4', 'Songti SC', SimSun, Georgia, serif;
--font-body: 'Source Sans 3', 'Noto Sans SC', 'Microsoft YaHei', system-ui, sans-serif;
--font-mono: 'SFMono-Regular', 'Cascadia Code', Consolas, ui-monospace, monospace;
```

- 标题使用 `Source Serif 4` 与 `Noto Serif SC`，形成正式但不过度装饰的编辑感。
- 普通 UI、按钮、表单和元数据使用 `Source Sans 3` 与 `Noto Sans SC`。
- 法条、长篇法律意见可使用 `--font-legal`，但不得为了“像法律文书”而缩小字号。
- 当前基准字号为 16px，正文行高 1.6；报告正文建议 1.75–1.85。
- 标题不要大面积全大写、过度负字距或使用细到难以阅读的字重。

### 3.3 字号层级

| 层级 | 建议字号 | 行高 | 用途 |
|---|---:|---:|---|
| 页面标题 | 32–36px | 1.2–1.3 | 页面名称、案件主标题 |
| 一级标题 | 26–28px | 1.3 | 报告主章节 |
| 二级标题 | 20–22px | 1.35 | 事实、义务、建议等章节 |
| 三级标题 | 17–18px | 1.4 | 卡片或段落内小节 |
| 正文 | 16px | 1.6–1.8 | 普通 UI、报告正文 |
| 辅助文字 | 13–14px | 1.4–1.6 | 标签、说明、时间 |
| 技术标识 | 12–13px | 1.4 | ID、哈希、trace、引用编号 |

小字号只能用于元数据和装饰性标签。不能用 12px 文字承载案件判断、法律义务或操作说明。

### 3.4 间距、圆角与阴影

| Token | 值 | 使用场景 |
|---|---:|---|
| `--space-xs` | 4px | 图标与文字、紧邻元素 |
| `--space-sm` | 8px | 控件内间距、短组间距 |
| `--space-md` | 16px | 默认组件间距、移动端内边距 |
| `--space-lg` | 24px | 卡片内边距、区块间距 |
| `--space-xl` | 32px | 页面内大区块、桌面主工作区 |
| `--space-2xl` | 48px | 页面段落或大型区块间距 |
| `--space-3xl` | 64px | 登录页或特殊 Hero 留白 |

圆角使用 `6 / 8 / 12 / 16px` 四档；胶囊状态使用 `9999px`。默认卡片使用 12px 圆角。阴影默认保持克制：普通面板使用 `--shadow-sm` 或 `--shadow-md`，弹窗/抽屉才使用更深阴影。

## 4. 组件规则

### 4.1 卡片与直接文字流

```css
.card {
  background: var(--color-surface);
  border: 1px solid var(--color-border);
  border-radius: var(--radius-lg);
  padding: var(--space-lg);
}
```

- `.card` 是信息分组容器，不是默认的段落容器。
- 普通卡片不设置蓝色顶边、彩色外框或悬浮位移；只有明确的状态组件才允许语义边线。
- 报告使用“页头卡片 → 摘要 → 直接正文 → 证据/动作”的顺序。
- 只有可点击卡片才使用 hover；静态报告卡片不能因为鼠标经过而移动。
- 卡片内边距桌面通常 24–32px，移动端 16px；同一页面不要出现多套内边距。

### 4.2 按钮与动作

- 主动作使用 `.btn-primary`：信任金背景、白色文字，页面中每个视图最多一个主要 CTA。
- 次动作使用 `.btn-secondary`：权威蓝边框或浅色表面，不与主动作争夺视觉重量。
- 危险动作必须明确写出结果，如“归档模板”“停用账户”，不能只放一个图标。
- 按钮最小高度 38px；关键触控目标建议不小于 44px。
- 所有按钮有 hover、active、disabled 和 `:focus-visible` 状态；禁用状态不能只靠颜色。
- 按钮文字使用动词开头：`分享案件`、`下载完整报告`、`创建模板`、`提交复核`。

### 4.3 表单与输入

- 标签放在输入上方，先说明字段含义，再放控件；不要只依赖 placeholder。
- 输入边框使用 `--color-border`，聚焦使用 `--color-ring` 和可见 focus ring。
- 同一表单的控件高度、圆角和文字大小必须统一。
- 错误消息紧贴字段或表单区域，说明“哪里错”和“怎么改”，不使用只显示红色的状态。
- 长字段、材料和备注支持自然换行；禁止用省略号隐藏用户正在编辑的内容。

### 4.4 状态、风险和进度

- 风险状态使用“颜色 + 文本 + 可选圆点/图标”的组合。
- 进度条的连接线连接节点中心，文字和节点在同一视觉轴线上；不要让线穿过标题或说明文字。
- 已完成、当前、待处理状态必须有不同的字重和颜色，不依赖动画表达状态。
- 流程节点文字桌面端居中，移动端按纵向阅读；流程区可以横向滚动，但页面本身不能横向溢出。

### 4.5 法源、引用和证据

- 正文中的引用标记紧跟对应判断，不单独生成“引用说明”尾注块。
- 法源入口用紧凑的“法源核查 + 数量”触发器，不占据报告主阅读列。
- 详细条文在证据抽屉中渐进展开；摘要视图只展示与当前判断相关的内容。
- 证据抽屉必须有关闭按钮、遮罩、键盘 Escape 关闭和明确的 `aria` 名称。
- 引用卡片显示：引用编号、法条/来源名称、具体条文、支持的结论和来源链接；长条文可在自己的区域滚动。

### 4.6 弹窗、抽屉和分享

- 弹窗用于短流程确认或编辑；抽屉用于查看法源、审计或辅助信息。
- 遮罩层不得改变底层页面布局；打开时锁定 body 滚动，关闭后恢复原状态。
- 弹窗宽度通常 520–680px，移动端改为底部抽屉或全宽面板。
- 二维码、分享链接等辅助内容不得替代权限校验；界面文案必须明确“打开时仍需登录并校验权限”。

## 5. 页面级模板

### 5.1 新建案件 / 工作台

顺序固定为：页面标题 → 案件统计/风险概览 → 审查问题 → 待审查材料 → 可选字段 → 提交动作。

- 首屏只保留开始审查所需的信息；高级字段使用折叠或分组。
- 审查问题和材料是两个不同字段，标签和间距不能混淆。
- 模板中心进入工作台时只填充问题和字段预设，不带入材料、结论、引用或审计记录。

### 5.2 案件详情 / 审查报告

顺序固定为：案件页头 → 状态/流程 → 审批摘要 → 完整审查意见 → 事实与缺口 → 法源核查 → 建议动作 → 审计记录。

- 审批摘要是供审批人快速判断的单段纯文本，推荐 120–200 字，接口允许范围为 40–240 字。
- 完整审查意见必须保留全部正文，不得为卡片高度或预览而截断。
- 报告标题和正文同一左边界；正文列保持窄而稳定，避免大段横向扫读。
- “下载完整报告”属于明确的报告动作，不能被隐藏在证据抽屉或更多菜单中。

### 5.3 用户管理、整改、模板中心和知识库

- 这些页面沿用同一应用外壳、页面标题、表单标签、表格/列表边界和空状态。
- 管理页面优先使用表格或直接列表；只有需要独立操作或状态摘要时才使用卡片。
- 空状态必须给出原因、下一步动作和权限/服务依赖，不只显示“暂无数据”。
- 模板卡片只展示名称、适用场景、审查问题、字段预设和操作；不展示案件材料与审查结果。
- 知识库页面应突出导入、索引状态、来源和可追溯操作，危险操作必须二次确认。

## 6. 响应式与可访问性

### 6.1 断点

使用以下语义断点，不为单个组件随意创建新断点：

- `1440px+`：完整桌面布局，保留较大留白；
- `1024–1439px`：桌面布局，收窄内容列；
- `768–1023px`：平板布局，减少并列列数；
- `≤767px`：移动单列，隐藏侧栏，显示移动页头；
- `≤420px`：压缩标题和操作区，保证按钮可触达。

至少检查 375px、768px、1024px、1440px 四个宽度。任何页面都不得出现横向滚动条、被页头遮挡的内容或无法关闭的浮层。

### 6.2 可访问性最低要求

- 所有交互控件使用语义化 button、a、input、select、dialog 或合适的 ARIA 属性。
- 键盘 Tab 顺序与视觉顺序一致；`:focus-visible` 必须清晰可见。
- 重要信息不能只用颜色表达；风险、成功、失败都要有文字。
- 动效时长控制在 150–300ms，并尊重 `prefers-reduced-motion`。
- 图标使用统一的 Lucide 图标集；图标按钮必须有 `aria-label` 或可见 tooltip，禁止用 emoji 代替功能图标。
- 表单错误和异步状态使用 `role="alert"` 或 `role="status"`，并让读屏器能够感知。

## 7. 内容与命名规范

- 页面标题使用简洁的业务名词：`用户管理`、`使用模板`、`案件详情`，避免“控制台”“中心”等空泛后缀。
- 状态使用稳定词汇：`待处理`、`审查中`、`待复核`、`附条件通过`、`已归档`。
- 风险先说结论，再说依据和条件；不要用宣传式语气掩盖证据不足。
- 所有“AI 结论”都要明确当前材料、召回证据和不确定边界；不把辅助判断写成正式法律意见。
- 案件、模板、法源、用户等业务对象的命名在 UI、API、示例数据和设计文档中保持一致。

## 8. 禁止项

- 禁止紫色/粉色渐变、发光、玻璃拟态和营销型 Hero 装饰。
- 禁止让正文铺满大屏；禁止为了“看起来丰富”堆叠无意义卡片。
- 禁止默认蓝色顶边、厚重彩色外框和装饰性连接线。
- 禁止多个区域同时吸顶；除明确页头外，正文和信息卡片随页面滚动。
- 禁止使用 emoji 作为功能图标、使用不可见的 focus 状态或用省略号隐藏关键判断。
- 禁止在页面 CSS 中写新的近似颜色、字号和间距；先查 token，再决定是否扩充 token。
- 禁止为了兼容旧布局保留重复组件、fallback 样式或过时入口；迁移完成后删除旧实现。

## 9. 实现与文档规则

1. 新页面先写页面级设计说明（若布局独特），再实现 React 结构和 CSS。
2. 组件优先使用已有 token、`.card`、`.btn-primary`、`.btn-secondary`、状态 chip 和表单基础样式。
3. 页面级 CSS 放在组件旁，跨页面 token 和基础布局放在 `frontend/src/styles/global.css`。
4. 新增 token 时同时更新本文件，并说明语义、取值和使用边界。
5. 视觉改动必须至少在桌面和移动宽度各检查一次；涉及报告阅读宽度时，应使用真实中文长文本检查换行。
6. 交付前运行 `npm run build`、`git diff --check`，并完成本文件的交付清单。

- [ ] 颜色、字体、间距、圆角、阴影均来自 token 或已有组件。
- [ ] 卡片只用于信息分组，报告正文使用直接文字流。
- [ ] 页头是唯一需要考虑吸顶的区域，其他内容正常滚动。
- [ ] 风险、状态、引用、缺口都有文字语义，不只依赖颜色或图标。
- [ ] 375px、768px、1024px、1440px 下无横向溢出。
- [ ] 键盘 focus、错误提示、浮层关闭和 reduced motion 均可用。
