## 修复方式

### 核验上下文

将私有核验输入中的 `interpretation_authorities` 改为 `context_authorities`：包含本次实际返回、受控法律库中已登记且 `can_cite_clause=false` 的补充资料，不再凭单一引用角色排除地方清单、行业指南和标准。未返回资料、未登记资料、内部制度与未引用的正式法条不因此被自动引入。

核心核验及报告分组核验使用同一批原文，并保留 `doc_type`、`citation_role`、`can_cite_clause`、日期、地域和对象。提示明确区分补充资料可用于核对内容、范围与手续说明，不能凭进入上下文就升级正式法条引用资格；确定性 claim 门禁没有放宽。

新增测试覆盖地方、行业与实施参考角色进入两阶段核验，并确认其仍不能支撑正式法条 claim；原有内部制度和未登记资料排除测试继续通过。

### 结构提取与现有语料

为 PDF 解析选择增加一项窄范围结构检查：原生文本层有完整“编号＋标题”，但结构化结果把它拆成孤立编号 Markdown 标题和单独的标题时，不采用这份结构化结果，沿用现有文本层选择路径。解析流水线版本提升为 `auto-text-first-v2`，使未来重新入库不会错误复用旧处理签名。

现有语料没有整篇重切。文本层隔离重建虽能还原收集/存储边界，但会把部分页码与正文拼成新标题，不能直接取代现有语料。最终依据源 PDF 与文本层核对，只纠正了 5 块已确认的路径：

- 上一章末尾 `k)` 所在块归回 `5 → 5.6 征得授权同意的例外`。
- 原来误挂在第 5 章的 4 块存储要求归入 `6 个人信息的存储` 及其子节。

122 块正文逐块保持一致；仅 5 块路径和相应引用标签更正，其稳定 ID 按原有定位规则更新，邻接引用同步更新。另 117 块稳定 ID 保持原值。没有删除原文、改写要求、补造章节内容或改变 `can_cite_clause`。

使用现有 `KnowledgeBase` 分代发布过程完成双库暂存、校验、激活和清理。正文和标题未变，原有 122 个向量全部命中缓存，新增 embedding 请求为 0。原语料、来源清单和知识库状态备份在 `data/review_runs/navigation_fix_20261019/corpus_before/`；修复映射及新旧 ID 保存在结构化结果中。
