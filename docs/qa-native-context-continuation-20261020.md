# 问答沿用原生工具上下文直接作答

2026-10-20，按用户决定取消“调查后重新组织上下文并另行作答”的实现。删除上一轮新增的交接摘要，让同一个问答Agent保留本轮工具对话并继续流式生成正文。

## 当前调用方式

1. 从原始问题、历史和当前可用材料开始，自主调查。
2. 每轮保留原始assistant消息、`reasoning_content`、`tool_calls`和对应tool结果；状态及资料增量继续按既有方式追加。
3. `finish`只登记所选引用、材料引用、未知业务事实及依据缺口。程序检查归属和引用完整性，再将引用编号映射作为该工具的结果返回。
4. 最终流式请求使用同一系统提示、累计消息链和相同工具定义。只将`tool_choice`设为`none`，直接生成正文，不创建新的作答上下文，不要求模型重写调查摘要。

`citation_registry`只关联本轮展示编号与原始chunk_id或网页URL，不含程序生成的法律结论，也不重新复制所有法源正文。原文及此前模型消息仍保留在同一消息链中。

预算耗尽时保留已有对话，关闭未执行工具调用，追加预算限制和引用登记控制信息，再生成有限回答；不清空历史、不启动补证或核验循环。

## 为什么最终请求仍保留tools

[DeepSeek思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)明确说明：带`tools`的后续请求应传回此前的`reasoning_content`，这些内容将纳入上下文；不带`tools`时，即使传回该字段也会被忽略。[Chat Completions接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)支持`tool_choice=none`输出消息；思考模式不支持的是`required`和强制指定某个工具。

因此，不能只保留消息而把最终请求中的tools删除。当前实现保留相同工具定义及原始推理字段，通过`none`停止继续调用工具。流式返回只向用户输出content，私有推理字段仍不进入公共问答响应或界面。

这保证程序不主动丢弃模型上下文，不保证模型不再进行任何新的思考；也不把模型先前判断视作法源或正确答案。

## 删除与保留

- 删除`QAAnswerPoint`、`answer_points`、交接引用映射函数和原先重建上下文的`answer_messages`。
- 调查和作答共用一个稳定的`PROMPT`，移除独立`ANSWER_PROMPT`及对应旧测试，不保留双路径。
- 客户端流式方法可携带工具定义并设置`tool_choice=none`；异常工具调用增量直接报错，不执行。
- 保留原执行预算、引用真实性与材料归属检查、流式usage记录、问答与整改审批隔离。正式审查调用方式不变。
- 本轮内部的模型上下文保持连续；追问仍沿用原有最近八轮历史及附件版本隔离规则，本次未扩展为无限会话历史。
