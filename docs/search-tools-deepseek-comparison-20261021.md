# 现有检索工具使用审计与 DeepSeek 官方搜索对比

日期：2026-10-21。检查真实调用轨迹，并对四条固定查询调用现有法律库、现有 Exa 联网搜索及 DeepSeek 官方 Search / Fetch。未替换生产检索配置、未增加语料、未重建索引，未调用回答模型、核验器或 Judge。检索排名及抓取可用性不等于最终回答的法律准确率。

## 结论

现有工具确实被 Agent 调用了，法条原文也真实进入生成和核验请求。受控库检索、精确条号读取及目录读取都有使用证据；近期正式审查没有调用联网搜索，不能期待只替换联网供应商就改变这些运行。

DeepSeek Search / Fetch 能直接接入，也有速度优势，但本次没有显示全面优于现有能力。无站点限制时，它找到了关键问答的省级官方转载；限定相同站点后，该问答未进入前十，Exa 排第二。上海题 Exa 直接取得官方 PDF 正文，DeepSeek 取得通知页，Fetch 未取得附件正文。

当前更合理的边界是保留受控法律库与精读，把 DeepSeek 作为联网搜索供应商候选。此次证据不足以支持整套替换，亦不足以宣称换供应商会修复查询遗漏或规则衔接错误。

## 二、DeepSeek 官方接口是什么

[官方 Search / Fetch 指南](https://api-docs.deepseek.com/guides/search/)提供独立 JSON API：

- `POST https://api.deepseek.com/v1/tools/search`：联网搜索，支持 query、count、ori_question、need_content 以及 site 等查询操作符。
- `POST https://api.deepseek.com/v1/tools/fetch`：抓取指定页面，返回 Markdown。
- 沿用 DeepSeek API Key；两种接口均按每千次成功请求 0.75 美元计价，失败和空结果不收费。

它们能作为现有原生 function 工具背后的供应商实现，不要求迁移 SDK 或改变整个 Agent 协议。独立 Search API 仍需我们调用并返回结果，不能把它等同于模型自动完成法律调查。

[官方 Responses 文档](https://api-docs.deepseek.com/guides/responses_api/)还提供另一种服务器执行的 web_search，但注明仅支持 deepseek-v4-pro，deepseek-flash 会忽略该工具。项目当前使用 deepseek-flash，本次测试的是原始 Search / Fetch API，没有换成 Pro 或改用服务器搜索。

## 三、实测设计

原始证据：`data/review_runs/search_provider_comparison_20261021/`。

四条查询固定为：

1. 历史 HR 免予条件查询。
2. 历史 HR 处理合法性基础查询。
3. 同一问题的中性衔接查询：向境外提供个人信息适用第十三条第二项至第七项时，是否还必须取得第三十九条要求的单独同意。
4. 上海自贸区 2025 版清单的主体、行业及未覆盖行业边界。

第一组使用各自现行检索形态：本地混合检索、生产 Exa 官方域名单、DeepSeek 默认联网搜索，各四次。本地 HR 查询沿用保存的事实，上海使用空业务事实；工具初始化与网络检索耗时分开，未创建审查任务。

第二组将两个联网供应商都限制在 cac.gov.cn 与 sh.gov.cn，均取前三个结果，并统一使用 httpx 传输。DeepSeek 使用文档规定的 site / OR 语法，Exa 使用 includeDomains。没有为某个供应商加入答案、问答标题或目标网址。

Exa 仍保留生产的 1200 字符正文上限，DeepSeek 使用 need_content=true；因此正文长度差异包含客户端提取策略，不能全部归因于引擎。排名与是否取得关键段落分别判断，不把网页数量与本地 chunk 数量直接比较。

随后对关键查询各补一次前十排名诊断，另做四次 Fetch 检查。没有调高生产返回上限。

## 四、结果

| 检查事项 | 受控法律库 | 当前 Exa / 同域对照 | DeepSeek |
|---|---|---|---|
| 宽泛 HR 免予查询 | 取得现行规则与相关问答，未取得目标七月解释段 | 同域前三为现行规则、2025 年问答及发布说明，未取得目标解释 | 默认及同域前三均未取得目标解释 |
| HR 处理依据查询 | 取得个人信息保护法等原文，未取得目标解释段 | 同域前三未取得目标解释，并包含旧征求意见稿 | 默认返回学者文章及第三方条文页；同域也包含征求意见稿，未取得目标解释 |
| 中性同意衔接查询 | 目标解释位于实际返回正文第 1，正常取得 | 现行配置与同域对照都在第 2 找到中央网信办七月问答，1200 字符文本已含关键例外 | 默认第 1 找到江苏网信办转载，正文含关键例外；同域前三及补查前十未出现目标解释，但取得个人信息保护法全文 |
| 上海清单 | 返回 2025 版具体说明，可继续精读；也混入 2024 解读及其他省份来源 | 当前名单仅取得网信办目录及一般规则；加入上海域后第 1、2 分别是清单 PDF 与管理办法 PDF，正文含主体和未覆盖行业边界 | 默认前三是律所解读；同域第 1 为发布通知页，后续为新闻、汇总信息，未取得附件正文 |

本地单查询返回二十五至三十一个片段，约 8581—11769 字符。上海查询仍把旧版解读排在前面，并带入其他省份清单；HR 查询亦有一般标准和地区专项来源。这说明现有查询与软排序仍有压缩噪声的空间，不能把“能找到目标条文”写成“检索已经整体最优”。单次返回顺序受组包与相邻片段展开影响，也不能直接当作全部底层相关性排名。

### 耗时与故障

- 本地四次查询平均约 0.51 秒，不含工具初始化；涉及现有 embedding 和索引缓存状态。
- 同域 DeepSeek 四次均成功，平均 2.31 秒。
- 同域 Exa 四次均成功，平均 7.87 秒。
- 首组生产 Exa 的 urllib 传输四次中有两次 TLS EOF 失败，另两次成功；统一 httpx 后的同域对照均成功。没有改生产传输实现，不能以一次对照确定失败根因。

这是一次、小样本、分组顺序执行的网络测量，不是稳定服务延迟基准，不能把它换算成完整 Agent 的提速比例。

## 五、工具设计本身发现的限制

1. **联网站点范围偏窄。** 当前名单含中央网信办等特定站点，但没有政府网主站 www.gov.cn、上海官方域和省级网信办域。DeepSeek 默认返回的部分真实官方资料会被现有名单拒收。“名单外”不等于资料错误，“官方站点”也不等于其中专家解读或征求意见稿可以当作现行法条。
2. **四条查询不保证都被执行。** WebResearch.search 的总结果上限是三个，首条查询取得三个可接受结果后直接结束循环。确定性复现提交四个查询，供应商只收到 query1。提高 Schema 到四条并未消除这个批次提前结束行为；本次保留复现，未顺手改变调用成本或生产策略。
3. **1200 字符是前部截取。** 本次七月问答的关键段落碰巧处于窗口内，完整法律文本和长文件的后部仍可能缺失。不能因结果含“正文”就认为整份文件已经读完。
4. **联网发现与取得可引用依据之间还有流程。** 正式审查中新来源仍要通过现有来源处理与引用资格流程，不能将搜索摘要、供应商 authority 分数或返回 URL 升级成已核验法条。问答可以使用取得的网页资料，但也须保留来源身份及实际内容边界。

前两项是我们工具契约、站点策略的问题；与模型推理能力不同，也不会只因换成 DeepSeek 就自行消失。建议后续先明确每个提交查询应否执行及合并策略，再决定是否替换联网供应商；受控法律库、精确法条读取和附件解析继续保留。

### 域名限制的建议

联网发现倾向于默认开放，以官方原站和直接相关性作软排序；存在来源冲突、时效疑问或需要取得具体法条时，再定向使用 site 查询。现有名单遗漏真实官方站点，不适合作为通用发现阶段的完整边界。官方优先是排序因素，不代表官方页面中的专家文章、征求意见稿就自动具备法条资格；非官方文章也可以提供调查线索，但其法律判断应回到原文。

来源发现、正文读取、引用资格分别处理：保留搜索发现的有用线索，按需读取原文及附件；正式审查继续使用已经记录和确认的效力、版本与引用资格。开放发现不代表开放任意页面作为正式法源，也不改变附件归属和审批要求。本轮只形成建议，没有修改生产域名策略。

供应商之间还存在摘要/原文交付、站点覆盖和附件抓取差别，不只是顺序。尤其外部引擎的内部候选不可见；本次只能观察默认与 site 查询的最终结果不同，不能把所有差异进一步断言为独立的索引缺失或排序故障。
