## 方法与采用决定

三条既有候选题，每条原版和候选各一次，六次完整执行后停止，无重抽样。顺序、提示全文、用例与文件哈希预先冻结于 `data/review_runs/retrieval_prompt_pilot_20261021/protocol.md`、`manifest.json`、`prompt_variants.json`。候选包包括三处改动，不能归因某一句的独立效果。

模型均为 `deepseek-flash`，Agent/正式核验为 low，正式评测Judge为 none。没有给QA增加语义核验或Judge。保留真实工具、语料、附件、冻结填报、预算及正式核验流程，没有注入指定查询、关键问答或调查摘要。逐题核对实际请求：用例内容、工具参数Schema、模型及思考设置相同，只有主提示与工具说明按候选包替换。新建评测会话的ID和时间不同，联网结果也未冻结；因此不是完全相同上下文的确定性实验。

**按产品路径分别判断。** QA候选发生引用交付失败且正文仍有实质问题，简单题累计输入明显增加，不采用。正式审查候选本次更集中、核验轮次更少，当时保留为独立复测候选，不能因QA未通过就一并否定。后续已按用户授权仅采用正式审查组合，问答保持原提示及工具说明。一次样本不能证明稳定质量、延迟或成本收益。

## 内容与工具行为复核

重要数据题两版主结论均正确。候选额外查询2026年变化及被告知后的两个月申报期限，回答由640字符增至1271字符，累计输入增加约275%。额外时限资料有原文，但并非判断小数量是否触发申报所必需；更短耗时不等于更少调查或更高效率。

HR问答两版都取得了2026年7月解释的关键原文，均在正文说明人力资源管理合法性基础下的同意例外。候选仍把“已说明用途，其他告知事项未知”改写成“告知书目前只写了用途”，并在后文将人数达到100万、出现敏感信息等直接写成回到安全评估，未保持已确认HR免予这一独立分支。此外出现两枚错误引用：一枚把已取得原文的chunk标识尾部当作引用标记，另一枚从正确标记中漏掉字符。最终程序拒绝交付，不能将部分展示正文算作完整成功。后续已单独修复该引用链路，未追改本次失败状态。

原版HR问答存在一次工具参数越界退回、两次实际联网及两次库内检索。第七个模型请求耗时190.704秒、记录42,064个reasoning token；最后作答另约20.5秒。这解释了本次长耗时伴随大量调查思考输出，而非引用修复或Exa单次请求耗掉全部时间。未通过删除历史、降低预算或增加候选样本来追求更短数字。

正式审查原版首次检索便取得七月关键解释，首稿已区分同意例外；候选未取得该解释，但将报告集中于免予机制，没有展开单独同意判断。因此不能把候选未出现该错误视为“正确检索并解决同意关系”的证据。原版发生4次核心核验，候选2次，另各1次建议与边界核验；这是本次正式审查用时差的主要组成。

正式核验确实纠正了实际问题：两版初稿都将关键事实未明的风险写为high，退回后改为insufficient_evidence；原版还修正引用关联与“某一种处理基础不成立就必须取得同意”的推导；候选把2022年的处理规模门槛与2024年的累计出境门槛等同，被退回后修正。这些是核验生效的轨迹证据，但最终两版仍有重核已确认制度、把一般原则扩展到具体文件条款核查的倾向。两版Judge均PASS，保留原评分，未据此判定报告已全面正确。
