## 实际改动

- 将评测入口注入的选择策略移入共享生产检索：每个查询融合关键词与向量结果，候选窗口五十；跨查询按最强命中选择，重复命中不额外累计分数，完整法条去重。默认关闭额外重排模型。
- 每批本地搜索返回的正文默认及最多十段，由模型按缺口缩小数量。十段指本批返回量，后续精读、网页搜索以及之前已读原文另计，不以新结果挤掉旧依据。
- 取消按来源追加支持片段及短法条自动补入。未选中的完整短法条只给定位信息，不通过导航偷偷附上全文；明确精读仍可获取完整原文。
- 正式审查替换调查收口和报告表达段落：只补会改变结论、风险或必要措施的法源缺口；事实未知保留条件分支；区分法定义务与建议；各栏目保持前提与支持强度一致。正式提示正文由973增至1098字符，净增125。
- 保留正式审查原有事实来源账本、材料及法源资格、原文精读、跨轮上下文、语义核验和暂停恢复；整改复核同步新的搜索数量参数。QA正文提示词保持上一批版本。

四次已采用真实搜索的候选分数离线重放，生产选择结果及顺序4/4完全一致。评测入口仅记录请求、结果和用量，不再替换排序与选择。532项相关回归通过。正式审查随后因真实504故障改用现有流式工具接收，收到完整参数后才执行；该修改后的133项相关回归也通过，两个测试集合有重叠，不相加。QA接收链路保持不变。

## 分开看检索与回答

纯检索评分不提供生成答案；复用已有旧版纯检索评分，新版六题另做离线复审。按固定的草拟观察点，首轮充分性旧5/6、新3/6；首次回答前旧6/6、新5/6。观察点覆盖首轮9/11→6/11，答复前11/11→10/11。单次候选测试、草拟观察点及单评估器不等于准确率。

新版唯一未完整覆盖的是小量敏感信息题的“安全评估分界”：已取得第五、八条，未取得第七条。当前24人且其他免予情形已排除的机制判断已有依据；“以后达到一万人转为安全评估”是答案延伸所需的依据。备案程序也是另行扩写，当前轨迹未读到对应条文。将这些列作回答侧无已见依据的延伸，不据此断言当前机制检索失效，也不为覆盖扩写而扩大首轮输入。

上海题旧记录实际上已有地方范围与全国衔接的原文，新答案对规则的使用改善，不能表述为旧版召回不到。包含答案的成对评估曾以“答案未写”给检索降分，甚至将实际存在的网页正文描述为仅链接；这些检索意见不采用，保留原始记录以便审计。

答复方面，HR题这次正确区分免予机制、告知、影响评估及单独同意例外；上海题未再照搬旧标准合同阈值。历史题仍有引文或表述瑕疵，小量敏感信息题仍有上述无依据延伸。不能把评估器correct标签当作全部主张无误。

## 正式报告

客户数据题完成生产链路，现有语义核验为supported，原评估模型也判通过。报告能区分“事实足以判断标准合同或认证机制”与“手续完成证明未提供”，没有因缺证明拒绝判断机制，也没有把报告交付当作审批。

但原文对照发现实质性漏检：risk_boundaries写“若当年累计非敏感个人信息出境达到100万人以上或出现敏感个人信息，应改按……第七条申报安全评估”。模型已经读到第七条全文，正文也写出敏感信息一万人门槛，边界栏目却漏了该门槛。这是回答/核验问题，不是召回缺失。故不能将本例作为报告整体正确通过。原始输出及评估结论均保留，人工发现另存。

HR条件未知题最初已取得24段原文，但非流式工具响应多次在约60秒后失败。第一次原状态续跑捕获HTTP 504；模型的一份初稿方向保留条件，但正文在“第五条第（二）项要求”处结束、claims为空，现有核验以不完整驳回，之后又遇到504。

正式Agent改用客户端已有的流式工具接收，仍等完整参数校验后执行。从同一冻结材料、填报与原状态再次继续，保留全部24段原文，新增检索/精读为0；两次流式模型响应和一次原有语义核验完成，未再出现504。本例成功不等于接口可靠性已全面验证；失败请求用量缺失，不能把缺失记作零消耗。

HR最终报告为insufficient_evidence，原有核验supported，原评估模型也判通过。但原文对照仍发现两项实质性问题：摘要将“集体合同尚未确认”写为“免予主张暂不成立”，正文把“未签订或无法证明”合并为同一安全评估分支；建议又要求“无论采用哪一分支，同步完成……单独同意”，没有保留已经读到的第十三条及2026年问答中的非同意依据。未知与不满足、一般义务与例外仍未稳定对应。上述均是已有相关依据仍错误运用，不能算检索失败。

两例都完成了运行与交付，但两例都留有人工原文对照发现的实质性问题。原评估器的2/2通过不采用为正式报告正确率，也不能称报告质量全部通过。保留本次检索和上下文迁移，不新增一致性复核调用，不通过继续堆逐题规则掩盖模型与核验器的局限。

本轮只验证两例正式报告，不覆盖其余七例、全部事实冲突/注入场景或正式审查的历史时点机制；原有离线回归不替代这些真实模型验证。没有为单题追加法条规则，也没有把后续未采纳的额外依据绑定或一致性修订调用接入产品。

## 唯一漏项的候选与补查定位

小量敏感信息题的第七条并非未进入候选：在主查询排第6、另一查询排第38，跨查询按最高分合并后排第27，落在最终十段之外。该条得分0.026585，第十段0.029199。前十段按最高分归属为机制查询3段、一般出境条件/同意查询2段、敏感信息定义及处理要求查询5段。当前没有重复命中累计加分；问题是相关性排序未表达子问题的重要性与跨文档边际信息，定义和处理要求的多个高分片段占据位置。

模型随后说明要核对安全评估门槛，但实际只精读第四、六条，没有精读已在最初查询中明确提到的第七条；最终却扩写未来一万人门槛。直接原因是排序选择遗漏，后续补查未补回；查询也将“只判断机制”扩展到了告知同意与多份定义/处理要求。第七条正文仅206字符，不需要增加返回段数来处理这一单例；优先验证十段内的语义去冗余与面向子问题的选择。该诊断只重放已有记录，没有重新调用模型或检索。
