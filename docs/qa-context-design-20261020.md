# 问答上下文、质量问题与缓存设计

## 诊断结论

对照本轮12条原始轨迹、作答前checkpoint和当前代码，质量问题发生在调查、阶段交接与正文生成三处。缓存历史总体复用正常，主要成本来自检索后新增的大批上下文和部分相同正文的重复更新。应先修复模型实际看到的信息及其身份，再验证提示能否正确应用这些信息。

本文件记录诊断与实现设计。上下文及用量改造已经完成，实施细节、免费回放和四条有限实测见[实施记录](qa-context-implementation-20261020.md)。下文原始诊断及旧轨迹不变，实测中尚未解决的法律质量问题单独保留。

## 从轨迹定位原因

| --- | --- | --- |
| HR已知前提被重新追问 | 材料读取完整且未截断；调查阶段conditions已质疑“确需”，该列表直接进入最终结果。正文再把非同意处理依据说成未知。 | 不是材料读取丢失。调查结果把“未经独立核验”混同于“用户没有提供”；交接没有要求保留本轮明示前提，正文继承了偏差。 |

来源元数据也有上游限制：本轮两份推荐性标准在语料中均为guideline/public_interpretation。仅保留这两个字段不能自动辨别所有标准性质，更不能新增一个凭标题猜测法律效力的标记。先保留已有资格、原文、标题及发布机关；精细语料分类需要另行治理。

## 缓存的实际情况

以下只统计调查调用，已排除评测Judge与未记录usage的流式作答。

| 指标 | 本轮值 |
| --- | ---: |
| 调查模型调用 | 52次 |
| 输入token | 1,372,493 |
| 缓存命中token | 999,680 |
| 未命中token | 372,813 |
| 总体命中率 | 72.84% |
| 12个首调用的合计命中率 | 93.21% |

首调用已受本轮之前的缓存及跨题相同前缀影响，不代表冷启动命中率。40个后续调用中，38个的命中token数不少于上一调用完整输入，其余两个分别少46、3个token。这是usage数量覆盖的诊断指标，**不是另一个缓存命中率，也不能替代逐字请求前缀审计**。它支持“现有追加历史总体复用正常”，不支持把总体72.8%诊断为缓存失效。

主要增长出现在检索之后：例如HR文件题一次从7,735增长至40,988输入token，该次未命中32,284；上海题后期输入达到67,891。新工具结果需要首次处理，不能要求全部成为缓存命中。保留更多冗余历史可能提高命中比例，却仍增加实际费用。

离线逐轮投影还找到67个“正文未变、只有分数/排名/查询归属变化”的证据更新，投影序列化合计52,843字符，其中上海24个。当前fingerprint覆盖整条hit，因此这些更新会再次携带原文。字符数不是token数，也不是已实现的节省额；完整原始请求未保存，不能据此精确复算账单。

检查没有发现本轮同一快照中的完整原文重复，也没有发现正文同时在observation和state中传两份：search/read的observation主要是编号、导航和续读信息，原文由state增量提供。因此不应为了“去重”删掉已经正确的这部分设计。

另有一个确定的统计缺口：stream_text读取SSE事件后只提取content，没有保存usage。DeepSeek当前官方接口文档说明末尾流式chunk可以携带整次请求usage；当前不是接口无能力，而是客户端没有采集。旧轨迹的12次流式输入/输出费用不能事后完整恢复。

## 上下文应如何组织

采用现有原生工具对话和执行循环，共用一套投影规则。存储中的完整运行状态与发送给模型的上下文分别处理，不把数据库字段全部当成模型需要阅读的内容。

| 层 | 内容 | 更新方式 |
| --- | --- | --- |
| 固定前缀 | 当前任务的稳定角色、来源身份规则、固定工具定义及顺序 | 一个运行内保持稳定；日期、问题、材料版本等放在后续消息。 |
| 原始输入 | 当前问题、相关用户陈述、已选择材料版本和实际读取的原文 | 原文保留来源与版本；同轮已提供页面不重复附全文。未独立核验不抹除明示前提，发现冲突则保留双方。 |
| 调查增量 | 新取得原文、来源资格、导航、续读、具体工具错误 | 只追加实际变化；相同正文按ID复用，检索分数变化不触发整段原文重发。 |
| 作答交接 | 相关原始前提、所选完整依据、真正未知业务事实、依据缺口 | 不传整个调查历史；模型调查判断明确标为非证据，不把conditions当作已核实规则。 |

### 先精简技术字段，保留法律语义

第一步保持相同检索范围、原文、条款条件、例外和预算。模型投影移除score、rank、retriever等技术字段；查询命中关系沿用已有query_results按ID表达。完整字段仍留在服务端轨迹。

证据指纹覆盖正文、版本、来源身份和引用资格，而不是检索排名。真实正文或资格变化必须提供显式更新，不能为了缓存隐去新版本、失效或冲突。来源级元数据仍只定义一次；同轮历史消息保持不变，新内容追加到末尾。

后续若采用更精简的检索呈现，应沿用已有来源导航和read_evidence按需精读；不能直接截断法律段落。服务端检索到、模型实际看到和仅导航预览应分别记录，引用完整性检查相应限制在模型本轮实际取得的原文。先做上述无损投影，不直接调低top_k或按长度丢证据。

### 让阶段交接带着依据及身份

作答所需引用保留doc_type、authority、citation_role、can_cite_clause及已有版本、条款、原文。正式法条、官方解释、地方清单、标准各按其性质使用，不能从“有效”或原文“应”推断本案强制义务。

finish中的待确认事项只承载真正未知、影响当前答复的业务事实；法律原文未取得属于调查限制。两者在内部交接中分开表达，不新增事实冻结或审批。原始材料中的明示前提保持可见，research_context仍只是检索工作投影，不覆盖原始输入。作答提示明确调查交接内容也可能出错，应结合原始前提与实际依据使用。

调查遇到改变结论的转引或例外，应按需取得对应原文。HR文件题缺第十三条就是本轮具体证据，不应做成固定“每题读第十三条”的规则。未知合同题则应保留成立/不成立分支；无法核实本身不直接触发法律后果，除非取得相应规则依据。

问答保留独立精简作答调用。新作答调用没有此前工具历史，仍需提供所选真实原文，不能只传来源ID。调查和作答提示不同，不能预设两阶段自然共享全部缓存，也不应只为命中率把全部调查历史塞回作答。

### 连续追问也纳入设计

当前每轮新建QAState，history只保留最近8轮问题和模型答案，没有相应旧引用映射；旧[依据1]不能直接解释成本轮[依据1]。本轮单次问答评测尚未覆盖该问题。

连续追问应保留相关用户原始陈述、材料版本及引用对应关系；旧答案作为模型陈述。复用此前原文时检查本轮材料选择、归属、时点和版本，不把旧结论变成已确认事实。需要重新组织上下文时，以可追溯原文和身份为准，缓存命中服从当前输入的正确性。

## 成本记录和验收

先补全非流式与流式的usage采集，按调查、作答、评测分别记录input、cache hit/miss、output、reasoning明细及耗时。reasoning若已计入output，不重复加算。没有usage时标记缺失，不记成零。终止、错误及末尾usage事件均用协议样本测试。

费用按调用时的模型和价格版本计算：命中输入×命中单价＋未命中输入×未命中单价＋输出×输出单价。只看命中率无法衡量实际节省。模型业务界面不展示这批内部元数据。

实现顺序：

1. 补齐usage与分阶段成本记录，建立完整计量基线。
2. 对共用上下文做无损投影，去除纯技术字段引发的整段重发；保留原有追加历史。
3. 完善问答交接的原始前提、来源资格和未知/依据缺口边界，再整理对应提示；正式审查保留事实账本、完整报告核验上下文及审批门禁。
4. 单独检查连续追问，保留引用、输入版本与用户修正的关系。

先用现有检查点做免费协议回放：语义字段及原文不得丢失；分数变动不重发原文，正文/资格变化必须更新；旧消息前缀不被改写；引用和材料归属检查仍成立。再用有限真实任务检查已保存的失败，不同时改模型、执行预算或rubric。验收比较每题实际费用、未命中输入量、峰值上下文、耗时和回答质量，不预设把命中率提高到90%或95%就是成功。

## 本轮已完成的小修

网页发现的说明、参数校验、Schema与执行上限已统一为4个查询；总网页调用预算仍为2。前端只将正文有效标记实际使用的法源片段放入“参考来源”及引用详情；未使用的法源与旧版片段保留在原始调查记录。材料引用沿用独立版本/摘录展示，不通过猜测正文语义过滤。

相关后端47项、前端19项测试及前端构建通过。用12份已保存回答离线检查，107个选中片段仅展示正文使用的91个，16个未使用片段均不进入前端来源；上海题仅展示2025版清单和所引国家规定两个来源。此检查没有重跑模型，也不代表此前四类语义问题已修复。

## 官方依据与复核数据

OpenAI Docs建议保留稳定历史和工具定义，把变化内容放在稳定前缀之后；具体缓存控制依模型而异，不能把其参数直接移植到DeepSeek。[OpenAI缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)

DeepSeek当前使用已持久化前缀单元匹配，默认启用且为尽力命中；其返回hit/miss字段，流式末尾事件也支持usage统计。实现以当前提供方协议为准。[DeepSeek缓存](https://api-docs.deepseek.com/guides/kv_cache/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)

离线诊断：`data/review_runs/qa_prompt_eval_20261020_citations/context_diagnosis.json`，包含分阶段usage、逐轮相同正文更新、作答前conditions及第十三条取得情况。原始评测结果与评分不变。
