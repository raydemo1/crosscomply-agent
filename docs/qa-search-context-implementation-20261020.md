# 问答检索上下文与工具Schema精简

2026-10-20，落实[上下文与工具归因方案](qa-context-attribution-20261020.md)。本轮修改问答工具契约、检索正文与导航的返回组织，并完成确定性回归；未执行新的真实模型评测。

后续[四题真实复测](qa-search-context-live-evaluation-20261020.md)已完成：首请求输入减少约48%，但整轮聊天模型估算费用增加约9.3%，回答质量有改善也有残留或退步。以下保留工程实现及确定性验证记录，不能据此视作行为验收已通过。

## 已落实

### 工具Schema与线索身份

- `QADecision.research_context`改用三字段`QASearchContext`：地区、行业、判断时点。只有`search_evidence`暴露该参数，其他工具不再携带事实定义。
- 问答发送给模型的state移除完整`facts`，仅投影已设置的三项检索线索。用户原问题、附件原文及来源不被改写，不通过新摘要填充事实。内部仍复用现有工具所需的`ReviewFacts`参数对象，没有增加问答事实确认流程。
- 工具说明明确按用户指定时点设置`as_of_date`。增量填写行业时保留先前地区和时点；缺省线索不代表用户没有提供业务事实。确定性测试覆盖参数实际传入共享检索工具，不能据此声称模型以后必然正确抽取历史时点。
- 材料说明区分“未经独立核实”和“用户未说明”；来源使用说明明确实施参考、解释辅助及有效状态的区别，要求正文清单与总结保持来源身份。

### 主要原文与候选导航

- 沿用现有混合检索、来源排序和工具名称。问答调用共享搜索时使用`include_supporting=False`，每个查询优先返回其主要命中原文；多个查询命中相同片段时去重。
- 主要命中沿用完整条文补全，不为压缩输入截掉同条的条件、例外。每个查询的主要命中不因跨查询来源合并上限而消失。
- 其他已召回片段及原有关键词导航按来源聚合，提供条款/章节位置、原始预览和可读取的编号；不生成模型摘要，也不根据是否支持当前结论删掉相反依据。
- 导航不是已取得的引用正文。需要额外依据时仍通过`read_evidence`读取来源、条款或章节；只在导航中出现的编号不能通过问答引用完整性检查。
- 后台候选继续保留，正式审查仍使用默认扩展结果；不新增相关性硬阈值、筛选模型、语料分类迁移或固定调查顺序。仅减少自动注入问答的正文量，不保证所有主要命中都相关，Agent仍需判断是否支持当前问题。

现有原生assistant消息、推理字段及tool结果继续累积，finish后沿原对话流式作答；预算及正式审查的确认、核验、整改、审批链路不变。

字符数减少64.54%。改动前的定义口径已与保存的实际请求工具散列核对；改动后的定义从使用模拟模型的真实`execute_qa`调用入口采集。快照及统计保存在`data/review_runs/qa_search_context_20261020/tools.json`和`schema_measurement.json`。

这不是token计数或账单节省比例，不能由此宣布原先约8,300 token的首请求已降至某个实测值。也未据提示整理和协议通过宣称回答质量改善。

全量后端 **789项通过，53.13秒**；相关文件Ruff及diff检查通过。新增验证包括：

- 主要原文保留完整条文例外，后台及导航仍有其他来源与相反依据。
- 未读候选不能直接引用，经实际精读后可引用且保持解释资料资格。
- 各查询主要命中均可返回，历史时点下未来候选不进入正文或导航。
- 问答不向模型投影未知审查字段，工具Schema仅检索工具包含三字段线索。
- 增量检索保留既有时点及地区，原生对话前缀继续保留。
- 正式审查扩展检索、来源续读、引用与材料归属、问答与整改审批隔离等现有回归继续通过。

本轮未改前端、未部署、未修改候选或旧评测结果。网页发现SSL问题需另行诊断，本轮没有将其归因于相关性或通过替换工具掩盖。
