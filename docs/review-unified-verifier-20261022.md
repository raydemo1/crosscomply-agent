# 正式审查：一次完整报告核验

2026-10-22。按用户确定的生产方向实现，不做模型、提示或架构 A/B。

## 实现

- `finish → 确定性门禁 → 完整报告核验 → 保存或退回`；保留原审批阻断。
- `semantic_grounding.py` 每稿正常一次 JSON/SSE 请求，同时核对核心判断、建议、问题项和风险边界。沿用一次接口或结构校验重试；这是异常修复，不是独立核验阶段。
- 输入包含完整报告及其 Schema、冻结填报、材料全文、事实账本、后续陈述、已取得法律原文及来源资格、网页发现身份和审查日期。问题项整体理解，字段分别定位。
- `claim_checks` 覆盖全部主张；其余两组 checks 仅返回问题。程序拒绝缺失或重复 claim 索引、虚构或错组字段、重复定位、无效证据编号，以及没有具体问题的概括性退回。精确引句仍可省略。
- `report_grounding.py` 仅组织报告字段目标，删除独立栏目输出模型、提示及模型调用。
- 保留 `SemanticVerdict`、缺口分类、证据不足处理和既有结果接口。修订反馈携带字段原文、原因、证据编号及业务事实或法律依据缺口；明确要求主 Agent 对照原文判断修订还是补查，不将核验意见直接当成法律条件。
- 未增加调查 Agent、强制检索或法律案例特判；未改 QA、检索算法和语料。

## 模型与协议

`LAWAGENT_SEMANTIC_MODEL=deepseek-v4-pro` 已写入本地 `.env` 与 `.env.example`。配置只覆盖正式核验模型；为空时继承任务 `model_id`，即使已有任务仍指定 Flash，显式覆盖也会生效。主 Agent 仍用 `deepseek-flash`，双方推理强度仍为 `low`，保留既有 SSE、读取空闲超时及请求总时限。

官方 `/models` 实际返回 `deepseek-v4-pro` 并列出 `low` 支持。随后仅进行一次无案件内容的生产客户端协议请求：JSON/SSE、模型 ID 和 low 参数通过，807 输入 token、291 输出 token，6.157 秒。没有缩短输出上限、静默替换参数或降级模型。

按输入每百万 14 元、输出每百万 40 元保守估算，不扣缓存优惠；这是基于官方美元峰值单价及 10 元/美元假设的上界估计，不是账单。该请求约 0.022938 元，原系列累计上界 25.467737 元，仍低于原 30 元边界。请求前按默认 65,536 输出 token 预留费用，该值只用于记账，未写入请求。

参考：[官方模型目录接口](https://api-docs.deepseek.com/api/list-models/)、[官方价格](https://api-docs.deepseek.com/quick_start/pricing/)、[JSON/SSE 和默认输出上限](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。

## 验证边界

确定性测试检查单次完整核验、跨栏目退回、稀疏反馈、证据身份、无效输出拒绝、配置隔离、既有程序门禁与 QA 隔离。协议检查仅证明请求可用，不证明 Pro 的法律判断能力或生产耗时收益。

没有法律案例付费重跑，没有生成新案件、审批或补库任务。没有添加旧版兼容路径，也没有删除历史案件或评测记录：本次保持结果接口，旧记录不构成实现障碍。

本轮差异、配置检查、QA 冻结检查及协议用量保存在 `data/review_runs/unified_verifier_20261022/`，最终测试数量见 `completion.json`。
