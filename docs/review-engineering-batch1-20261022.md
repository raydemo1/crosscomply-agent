# 正式审查第一批：流程与派单契约修复

直接回答冻结。本轮完成两个 P0 的程序复现、修复与离线回放，没有进行模型调用、真实 Agent 评测或十题重测。三段语义核验、模型、推理强度、审查提示及证据门槛保持不变。

## 1. 无具体补充事项的未完成审查

改前可直接执行真实 `run_agent` 的预算耗尽分支复现：预算为零且没有已定位事实、法源缺口时，生成 `insufficient_evidence` 报告；整改映射没有任务，案件却进入 `needs_info`。该程序复现禁止模型、调查和核验调用，不涉及模拟法律质量。

现在按已定位的责任分流：

| 条件 | 路由 |
|---|---|
| 有具体业务待确认事项 | `needs_info`，事实任务仍只从最终清单生成 |
| 有法源缺口、核心网页影响或已有法源暂缓 | `pending_source_verification` |
| 审查或核验未完成，但无具体业务/法源缺口 | `run_failed`，由审核人重试；不虚构申请人任务 |
| 审查完整，且无送审前未完成任务 | 保持现有审批流程 |

`review_has_missing_information` 继续承担审批阻塞检查，不因改变案件路由而把证据不足视为可以放行。显式 `unsupported` / `uncertain` 的核验状态同样阻塞审批。

预算耗尽时，最后一份草稿已经列明的业务问题与最后核验返回的事实缺口合并去重后保留，不再只取核验器的 `missing_facts` 而丢掉草稿清单。没有具体缺口时，交付说明改为由审核人重试或人工复核，不再笼统要求申请人补事实。

### 重试路径一起验证

仅改案件状态仍不够：该任务已成功生成有限报告，在任务表中是 `succeeded`；原重试接口只接受失败任务，或只恢复整改清单保存失败。

现允许审核人重试确属未完成的已交付报告：

- 仍校验审核人权限、案件 `run_failed`、当前最新任务及相同冻结材料/事实快照。
- 任务存储再次检查报告确实需要重试；PostgreSQL 使用行锁和原状态条件更新，重复排队被拒绝，正常完整报告不能借此重跑。
- 审核人发起重试时，清空该次已经完成/耗尽的 Agent 工作状态，从相同冻结输入开始新的执行尝试；不增加旧尝试预算，也不在有限报告交付后自动重试。
- 旧报告在新报告完成前保留，重试事件保存原报告与 trace；既有尝试记录保留。普通运行失败的恢复状态处理不变。
- 不创建新的案件状态、接口或数据库迁移。没有自动修改历史案件。

## 2. 问题项漏入派单清单

审计入口：

```powershell
D:/miniconda/miniconda/python.exe scripts/audit_review_workflow.py --output <新的结果文件.json>
```

只读回放 `data/review_runs` 中 120 份 `payload.json` 报告，逐份记录 SHA-256。104 份存在 `issues.unknowns` 与 `missing_information` 精确文本关联差异。它们覆盖多个历史版本，**不能把这个数字当成当前版本的漏派率**，更不能把同义改写全部算成漏项。

人工确认的一处实际漏项：

- 报告：`review_remaining_six_20261021/agent_material_conflict_001/payload.json`。
- 问题项要求确认：“两份材料差异的具体原因（统计口径执行、系统取数、是否含免予情形对应人数等）”。
- 最终清单只有实际累计人数及全年预计人数，没有要求解释差异原因。
- 当前派单只读最终清单，因此没有生成这个已在问题项提出的确认事项。

另以附件指令注入报告作对照：问题项分三条描述机制、认证、告知/同意，最终清单将其合并成两个完整问题；精确关联虽不一致，不能据此认定内容遗漏。原报告、原成绩及派单记录均未改写。

### 最小提交检查

`validate_business_questions` 在正式 finalizer 中检查每个 `missing_information` / `material_conflict` 问题项：

1. 必须明确列出待确认业务问题。
2. 每个 `unknowns` 条目都须逐字登记在 `missing_information`，忽略首尾空白；法源缺口不算业务问题。
3. 漏项返回问题标题及具体遗漏文本，由既有工具错误反馈处理，提交通过前不运行独立语义核验。

不从 `issues` 自动补清单或派第二套任务，不使用字符串相似度，也不自动把旧报告中的疑似同义项合并。精确相同问题仍只生成一个任务。

这强化的是已存在的字段契约，不证明模型提出的每个问题都有法律必要性。由于精确检查也会退回同义改写，额外返修成本尚未通过真实模型调用测量；本轮没有增加核验器调用、轮次或 Agent 执行预算。

## 3. P1 与后续批次

确认填报与材料引用仍保持身份区别。现有 `legal_gap` 的确定性门禁和 `test_legal_gap_without_material_fact_is_rejected` 继续生效，本轮未放宽。
