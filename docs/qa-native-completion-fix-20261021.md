# 问答原生正文完成协议修复

日期：2026-10-21（UTC+8）。

## 问题与处理

原问答循环只接受工具调用。DeepSeek 在 `tool_choice="auto"` 下返回完整正文时，程序仍要求调用 `finish`，再追加一次正文生成请求。第一次答案留在历史中，造成重复生成及旧答案影响后续生成的机会。这不是独立语义复审，但属于程序引入的多余作答步骤。

不能简单改成强制工具调用：DeepSeek 官方 Chat Completions 文档明确说明，思考模式暂不支持 `tool_choice="required"` 或指定工具，使用会返回 HTTP 400。[接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。官方还要求在思考工具调用过程中保留之前的 `reasoning_content`。[思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

本次保留现有接口、思考设置及完整原生对话，改为接受合法的原生正文完成：

- 纯正文：直接流式交付该正文，不补调 `finish`，不请求第二份答案。
- 正文与单独的有效 `finish` 同时返回：交付原正文，保留经过检查的材料引用与待确认条件，关闭工具调用记录，不请求第二份答案。
- 只有 `finish`、没有正文：沿用同一对话生成一次正文。预算耗尽也仍根据现有资料生成有限答复。这两种情况在此前尚没有正文，并非复写。
- 正文开始输出后连接中断：记录失败及已持久化的部分正文，不自动重试生成另一份答案。
- 工具调用随附的过渡文字：继续执行工具时清除暂存文字，避免把它保留为最终答案。

客户端新增带工具的 SSE 解析，分别组装正文、工具参数分片和私有思考。只将正文传给展示回调，工具参数与私有思考不进入回答展示。

## 引用与边界

原先引用编号在 `finish` 预选后生成，无法支持模型在同一次响应里直接写出可靠编号。现在资料实际取得时即分配本轮稳定编号，并随原文提供；预选与最终展示不再重排编号。

正文可以引用本轮已实际取得、但未写入 `finish` 预选清单的来源。程序仍拒绝未取得的引用编号、未读正文编号，以及不属于本轮材料版本或不匹配原文的材料引用。来源性质和引用资格保留；导航与摘要不会因此升级为法条。最终参考来源只保留正文实际使用的编号。

正式审查不启用直接正文完成，仍要求结构化提交，并沿用现有事实确认、核验和审批流程。本次未修改检索排名、调查预算、法律质量提示词或前端。
