# 正式审查核验证据上下文修复

2026-10-20，检查正式审查主Agent与独立核验器的上下文传递。主Agent调查、提交报告和退回修订本来就使用同一条原生工具消息链；本轮修复的是核验器输入中遗漏已取得法条的问题。

## 复现及原因

`ComplianceAgentTools.finalize`已向核验器提供按审查时点过滤后的证据及既有完整条文。遗漏发生在`SemanticGroundingVerifier`内部：

- 报告claims或issues引用的原文进入`cited_authorities`。
- 未引用原文只有在`can_cite_clause=false`、且属于已登记法律资料库时才进入`context_authorities`。
- 因此，已取得但未引用的正式法条因`can_cite_clause=true`被过滤；其前提、例外或相反规则在核心及后续栏目核验中都不可见。

先添加确定性复现：报告只引用一般规则，输入证据另含未引用的例外条文。是否同时提供完整Chunk元数据的两种情况都复现`context_authorities=[]`；修复后两种情况均通过。

## 实现

未引用、仍具法条引用资格的本轮原文现在进入核验背景。原有法律解释、地方清单、行业指南和标准按原资格保留；内部文件和身份不明的非可引用资料不因本次修复自动进入法源背景。未取得的整库条目不会仅因出现在`chunks_by_id`中就被添加。

核心及建议、风险边界、问题栏目共用同一证据集合。原文按chunk_id去重，保留传入的完整条文或实际片段、来源、条号、章节路径、版本、效力、地域、对象及引用资格；不增加检索、读取或核验模型调用。

提示说明“未引用法条”与“已引用原文”的区别：背景原文可以揭示遗漏的例外或限制，但不能替报告补造未表达的限定，也不能替代claim已提交的引用关系。程序不把背景编号自动写入报告，不提升指南、标准或内部材料的资格。

原报告、事实账本和确认快照不改写。独立核验仍返回意见，由原主Agent沿用完整工具历史及原生推理字段修订；引用真实性、材料归属、事实确认和审批要求不变。没有新增交接摘要、兼容路径或固定法条判断。

## 验证

- 定向 **148项通过**，覆盖核验输入、修订、原生工具对话、事实来源、权限和任务接口；Ruff通过。
- 最终全量后端 **785项通过，54.78秒**，包含既有问答及正式审查回归。
- 新增两种元数据场景，验证未引用例外原文同时进入核心、建议和边界核验，且不会自动变成报告引用；重复编号不重复发送，未取得的整库条目不进入输入。
- 新增原生主Agent退回修订检查，验证原稿、原生推理字段、例外原文及完整核验意见保留在同一条消息链，最终仍由原Agent提交修订稿。
- 原有非可引用资料资格、引用及材料归属、缺口审批拦截和问答隔离回归继续通过。

本轮未执行真实模型评测、未重跑历史轨迹或上海真实任务。这些检查证明原文传递缺口已修复，不证明核验模型一定正确理解例外，亦不证明法律判断稳定性或成本收益。核验输入可能因补齐法条变长，按编号去重只避免重复传递，不保证总token下降。
