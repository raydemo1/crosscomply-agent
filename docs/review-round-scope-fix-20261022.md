# 收口范围与每轮预算修复（2026-10-22）

## 本次范围

只调整收口契约、现有人工继续节点的预算，以及联网上限。不新增报告字段、不增加核验阶段、不设置强制检索顺序，也不以程序关键词判断法律适用。

## 为什么上海当时没有继续查

上次真实运行结束时：决策9/16、受控检索3/5、原文读取5/10、联网1/2，未到任何上限。Agent主动finish，核验器接受证据不足报告后结束了调查；报告中的legal_basis_gaps随后触发法源待核与审批阻塞。

原finish允许“已明确关键证据缺口”即提交，容易把列出问题当作完成调查。原Schema虽说范围外事项不登记，核验对缺口是否真的影响本案没有足够明确的检查要求。

## 改动

1. **收紧finish。** 当前目标已有充分依据即可提交；关键依据仍可调查时应定向补查；针对必要缺口已经尝试仍无法解决时，才提交明确限定的证据不足报告。不要求耗完预算，不要求为了结束再搜一遍。
2. **收缩法源缺口。** legal_basis_gaps仍为原来的字符串列表，只登记已针对本案调查后仍缺失、且会改变当前目标内判断的依据，并说明具体影响。未读整份文件本身不是缺口；范围外或可删去的延伸判断不阻塞本案。必要延伸说明可放风险边界。
3. **核验检查过度阻塞。** 使用现有完整核验，逐项检查legal_basis_gaps的必要性；发现不相关阻塞时定位原字段并要求主Agent缩小报告范围。程序不静默删除缺口或改写风险，不绕过真实证据不足和引用门禁。
4. **每轮预算。** 决策、检索、读取、联网四类额度按一次连续自主调查计算。现有人工补充/审核人指引被有效接收后开启新一轮；重新启动工作进程、恢复checkpoint、模型修订均不自动刷新。累计计数、编号、证据、历史和去重读取记录保留，新增内部budget_start记录轮次起点，remaining_budget由程序计算并提供给正式审查Agent。
5. **每轮联网5次。** 正式审查及QA的max_web_searches默认改为5，指search_web工具调用次数；单次最多4个查询的原参数契约不变。QA新一轮用户问答仍使用现有新run机制，无新增审批或事实系统。

人工继续的预算更新放在answer_agent：现有权限、等待状态和gate_id检查成功后才更新起点，非法或过期回答不会刷新。允许最后一个决策名额用于request_input，新一轮不被旧累计次数立即卡住；gate_id及历史步骤编号保持递增。保留跨轮原文读取历史，去掉原来全任务32条读取记录的长度限制，避免多轮合法读取后无法恢复。

这里的人工继续不是飞书最终业务审批；最终审批状态与审批门禁均未改。审核人显式重新运行与原有重试流程仍由原接口处理。

## 一次真实核验诊断

只重放上次上海最后一次完整核验的固定报告和完整证据，没有重跑四题或增加Judge。模型deepseek-v4-pro/low，一次请求、零重试。请求发送前逐项断言业务输入、报告、法源、冻结材料和网页发现完全相同；只更新核验说明及report_schema的字段说明。

结果：旧报告原先被接受，新核验将三个legal_basis_gaps均定位为unsupported：

- 配套办法/指南未全文阅读：报备细节不改变“先看负面清单”的当前结论，不能仅据未读全文阻塞。
- 非自贸区全市适用依据：本案已知在自贸区，属于范围外分支。
- 临港特定行业一般数据清单衔接：行业是否相关尚未明确，不阻塞先看负面清单的答复。

核验同时指出一条claim引用支持范围不足，仍返回unsupported，没有直接放行原报告。这符合“去掉不必要阻塞，但保留真正问题”的目的。

耗时83.625秒，费用按既有保守单价估算0.93624元，非账单实扣。准备阶段曾遗漏已保存网页发现，被发送前的一致性断言拦住，修正后才发起唯一一次付费请求，记录在preflight_events.json。

本次诊断没有让主Agent重新生成完整上海报告，也没有修改旧报告或旧评测边界。它提供一次正向筛选信号，不证明长期稳定性，更不证明所有法律判断已修复。
