# 第一批：收紧调查目标与按需取材

2026-10-29。五道代表 QA 已完成开发模型真实执行，并由原评估模型对新旧轨迹匿名成对复审。结论是输入减少、最终核心证据覆盖保持，但首轮充分性下降；部分无依据扩写减少，事实推断和例外适用仍不稳定，不能宣布回答质量通过。

## 当前采用版本

用户已确认采用本批方案。正式代码保留本批提示词、按需取材及原生直接回答方式，不接入后续的依据摘要、额外一致性修订或其他新增模型调用。后续小型试验仅作为本地记录保存，三个未采纳的试验脚本/测试已归档到实验目录 `unadopted_answer_pilots_20261029/`。没有切换默认模型配置或部署。

当前相对最初基线少 21,441 tokens，约 9.6%；相对紧邻的上一轮少 71,728 tokens，约 26.2%。此前 26.4% 指输入 token，不能与输入加输出的总量混用。

最初记录的首轮决策在后续运行中重放，统计已将原始首轮规划输入、输出补回且只计一次。模型请求从最初12次增至当前17次，更多精读与续答回合抵消了一部分上下文压缩收益。不同单题并非都降低：敏感信息题和免予边界题相对最初增加，其他三题降低。

这仅比较业务成功链路，不包含评审、研发试验、失败尝试、embedding/rerank或部署运行支出。最初部分题存在首轮时点处理偏差，规划和检索轨迹也不同，属于已有记录对照，不是相同规划下的因果消融或稳定平均降幅。完整逐题凭证为实验目录 `accepted_qa_token_comparison_20261029.json`，采用版本源码哈希保存在 `accepted_qa_version_20261029.json`。

## 本批改动

- 替换 QA 原有调查与回答段落：围绕当前判断，只有会改变答复的法源缺口才继续调查；允许按已知法名、条号直接精读；事实未知保留条件分支；无依据且非必要的延伸省略，建议不写成法定义务。
- 调整既有 summary 描述，使补查目的说明当前还缺什么依据。
- 本地搜索增加 max_chunks，由模型选择跨所有子查询融合后返回的正文数量，默认及上限十段；结果截取发生在融合、证据选择之后，完整条文的条件与例外不拆开。
- 继续保留跨轮原文、去重、无邻近扩展和元数据合并，不使用额外重排模型。

QA 系统提示正文由 1,293 增至 1,340 字符，净增 47 字符；工具 schema 增量另计。没有为个别题加入目标法条或正确答案，没有按主题增加特例规则。

生产模块改动在 `law_agent/review/qa_agent.py` 和 `law_agent/review/agent_tools.py`。精确的本批前后补丁保存在实验目录 `qa_scope_batch1_design_20261029/production_change.patch`，不把工作区此前已有修改算作本批交付。

## 验证方式

选取简单数量题、规模未确认题、敏感信息题、HR集体合同未确认题和免予边界题，共五题、八项草拟核心需求。包含确实需要补查的场景，避免仅通过过早停止使输出变短。

开发模型使用 DeepSeek-V4.1-Flash-1017，完整运行原生 QA 链路；新规划自主生成，不提供缺口答案。保持上一轮的候选窗口和实验排序策略，仅增加模型可选的返回数量。实验排序仍由评测入口注入，不能将本轮效果描述为所有生产检索路径已获得同等验证。

旧结果取自 qa_native_history_20261029，不重新运行旧开发模型。逐题断言新旧 question、material/intake 完全一致。原配置 deepseek-flash 对匿名 A/B 两份答案和各自实际已见正文复审，标签轮换，不给策略名或成本；核心证据覆盖与答案主张问题分开记录，不把扩写带来的依据缺口计入核心检索需求。

单次运行、五道选择性候选和单评估器意见都不是产品准确率。规划未冻结，不能将差异全部归因于某一条提示词或 max_chunks 参数。

## 回答变化与未解决问题

数量题去掉了旧答案中影响评估、单独同意、一般备案期限等缺少已见原文支持的扩写，也修正了引用错配；仍有一句非必要的新旧法规状态说明。

敏感信息题没有继续扩展自动化决策和关闭推荐选项，并明确推荐性标准的参考性质；原评估器本轮未标出其主张问题。答案字符并没有明显减少，说明取材范围、表达强度与文本长短是不同指标。

规模未确认题仍把日均处理量用于推断累计出境人数，给出“很可能需要先申报”等倾向性结论。HR条件题仍将“集体合同尚未确认”写成当前免予不成立，并继续扩写单独同意义务。这些问题没有被本批提示词解决，不能因证据齐全而判为正确。

原评估器将新免予边界题标为 correct，只指出条号错误。人工对照原文还发现其末段写道：“一旦出现敏感个人信息……第五条的豁免即不再覆盖该部分出境活动”。实际已见第五条中，第（二）项HR情形没有这个排除条件；“不含敏感个人信息”限定第（四）项小量普通信息情形，末款另排除重要数据。这里将不同项的条件混用，属于有原文仍作出过度范围声明。该漏检记录于 manual_findings.json，原始评审保持不变。

因此不使用原评估器 correct 标签或原始问题计数宣称准确率提升。当前证据支持“减冗余有收益、部分扩写收敛”，尚不支持“无依据声明已稳定减少”。下一批应集中处理事实状态、适用条件与最终结论的对应，保留这次发现的错误作为回归样本。
