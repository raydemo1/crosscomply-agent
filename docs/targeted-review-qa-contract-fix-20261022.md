## 原因与修复边界

1. **协议要求遗漏，已修复。** DeepSeek JSON模式要求消息含JSON字样。原完整核验提示未包含，小协议检查却包含，导致小检查成功、真实请求被生成前拒绝。已补生产提示中的JSON要求并增加生产请求回归测试；模型ID为deepseek-v4-pro，并非模型不存在。恢复HR时沿用原核验用户载荷，没有重新调查或挑选答案。
2. **网页字段契约未完整告知，已修复。** 原Schema仅对core强调URL；程序却对supplement、execution_detail、core一律要求URL，且仅接受新官方来源或有更新迹象的已入库来源。现在Schema明确所有分支，正式Agent上下文主动给出eligible_material_web_urls，提交门禁与上下文共用同一个资格计算函数。来源资格、审批阻塞和引用规则不放宽。
3. **约束分散，已集中说明。** 有阻塞法源缺口时必须证据不足、无确定路径；问题项unknowns须逐字复用最终missing_information清单。后者原先已写明，并非新增规则。现在报告根Schema集中说明字段关系，不增加通用法律判断提示。
4. **模型推理仍会出错。** 人数QA已经写出应按当年累计去重人数计算，却又把日均处理量推成已达到出境门槛，不能归因为隐藏的提交约束。HR最终报告也重复审查了一些已确认事实。本轮没有声称靠Schema说明解决这些问题。

HR核验输入已包含2026年官方问答，仍在初稿中判断错误；首次成功完整核验的顶层status为supported，但部分claim为unsupported。程序正确取更严格状态并退回修订，最终同意表述得到纠正。单题结果不能证明稳定收益或归因于某一提示修改。另发现的省级官方口径影响原集体合同题评分边界，需专业复核，不修改冻结题目迎合结果。
