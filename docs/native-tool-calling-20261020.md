# 原生工具调用迁移

本轮按用户授权，将审查、合规问答及整改复核的动作选择迁到DeepSeek原生工具协议。仍使用现有`/chat/completions`及标准库HTTP客户端，没有更换SDK、模型或接口地址，没有新增依赖。

## 最终实现

- `OpenAICompatibleClient.chat_tools`通过`tools`注册函数，使用`tool_choice=auto`。普通原生调用不依赖Beta strict模式，也不强制思考模式调用指定函数。
- 每个工具单独提供用途、参数和所需的嵌套定义；检索工具不再携带完整报告字段。主Agent不再要求普通content返回统一动作JSON。
- `AgentDecision`、`QADecision`与`RemediationDecision`保留为程序内部参数校验及执行结构，不再是模型需要输出的大动作对象。没有保留JSON动作接口回退或模式切换分支。
- 模型请求经对应工具结果确认，保存assistant消息、tool_call_id及思考模式所需的reasoning_content。错误作为对应调用的结果交回，后续动作由Agent自主选择。
- 一次响应中的普通工具调用按返回顺序执行，每个动作仍消耗现有执行预算。finish和request_input须单独提交；包含它们的混合批次逐项返回错误，不静默丢弃或提前执行其他调用。
- 协议历史、待执行调用和状态投影记录进入私有checkpoint，支持已有执行恢复与人工追问续接。材料和法源原文只在首次取得或实际变化时附回，历史正文不删除；后续状态更新明确采用按标识合并、其他字段覆盖的语义。
- 工作事实与执行状态仍由原循环更新；动作选择得到隔离的状态视图，仅共享其专用协议会话，避免调用方改写运行事实。
- 公开JSON响应及问答评测导出移除tool_session，问答流只输出正文。私有协议数据保留在后端，满足多轮API要求，不发送到前端。

正式报告、语义核验和整改建议等结构化结果节点继续使用自己的结果契约。没有新增独立核验、修改法律规则、放宽引用资格、调整事实确认与审批，或改动22条候选案例标准。原有工作区其他改动保留。

## 已完成的验证

- 后端全量750项通过，Ruff与diff检查通过。
- 新增原生协议回归覆盖auto调用、思考数据续接、多个工具结果的编号关联、参数错误后继续运行、混合终止批次不执行、预算耗尽后关闭未执行调用、恢复执行与人工输入、原文增量传递及公开响应不泄露协议历史。
- 原六稿历史回放继续验证原稿和完整核验意见进入后续输入；它是已保存决策的协议回放，不是新的真实模型法律审查。
- 真实DeepSeek `deepseek-flash`、low思考模式，通过实际问答worker完成一次附件概括任务：read_material → 对应tool结果 → finish → 流式答复。两次工具模型请求、一次正文流式请求，保存的观测耗时4.219秒。没有为取得更好结果重复运行。

真实冒烟记录：`data/review_runs/native_tool_calling_20261020/qa_protocol_smoke.json`。记录调用标识、工具名称、思考数据是否续接和答复，不保存私有思考正文。输入为内存会话和受控附件，调查工具受控；该测试验证官方接口与问答执行链路，不涵盖完整ES/PG检索、正式审查真实模型运行或法律准确性。

本轮没有运行新的上海完整审查或12+10全量模型评测，没有部署。
