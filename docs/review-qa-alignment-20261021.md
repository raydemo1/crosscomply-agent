# 正式审查与问答的调查、上下文和引用对齐

2026-10-21。本轮检查并修改正式审查实际执行器及旧结构化报告生成路径，保留工作区已有改动。没有采用上一轮未证明稳定收益的问答规则/示例候选，没有新建 Agent、核验器、兼容路径或数据库迁移。

## 已有共用与应保留的差别

问答和正式审查此前已共用原生 tool calling、保留接口返回的思考和工具历史、状态增量上下文、调查执行函数、检索与来源精读、网页查询上限、分页及错误反馈。正式审查也已具有完整退回理由、原稿、可降级定位、栏目全文背景和已支持内容稳定修订的规则。

正式审查提交结构化 claims，直接选择原始 `chunk_id`，由程序生成 `citation_ref`。因此不需要把问答自由正文的标记格式强行移入正式报告 Schema；统一的是模型选来源、程序管身份与展示的职责。

正式审查继续执行事实快照、材料归属、正式法条引用资格、独立核验、事实缺口和审批门禁；问答仍不进入这些正式流程。初始材料原文不自动成为已确认事实。

## 确认的缺口与修改

### 1. 原文和完整报告背景

旧结构化报告提示截取材料前 3000 字、每条来源前 1200 字，同源支持及相邻来源另有数量截取。这可能删去尾部事实、条件及例外。现在直接传递本次实际取得的完整证据集合，与 Agent 使用相同的同源元数据去重投影；材料不再静默截取。代表、支持和相邻来源只保留导航身份，不再重复嵌入或截断原文。

核心核验此前只收到核心报告字段，栏目核验才有完整候选报告。现在两个核验阶段都使用 `report_background`，完整报告在每次请求内只传一份；核心阶段由 `core_targets` 限定本轮对象，栏目阶段仍由 `report_units` 限定。背景是待核候选，不替代原始事实与法源，也不能替错误断言补造限定。

参考资料并非在正常路径上一概漏传：已有逻辑会把具备合法语料元数据的解释、标准等资料送入核验。该资格边界继续保留，没有把全部材料无差别变成法源。报告声明使用的参考资料现在也会明确进入已引来源集合，仍携带原始 `citation_role`、`can_cite_clause`、时点和范围。

### 2. 实际使用来源与调查记录

正式交付此前把全部已取得证据分组展示。现在法律 claims、issues 支持来源与新增 `reference_chunk_ids` 一起决定交付来源；后者只登记正文实际使用的解释、标准等参考片段，不形成正式法律 claim。

程序检查这些 ID 是否来自本次可用证据，沿用时点与资格检查，并生成所有来源编号及元信息。未使用来源不进入交付引用列表，但完整已取得证据、来源包及核验背景保留，未引用的相反规则或例外仍可参与核验。

“实际使用”由报告提交者声明及独立核验判断，代码只能检查来源身份，不能靠 ID 存在自动证明其语义相关或法律结论正确。

### 3. 段落引用位置

旧标记注入逻辑会用共有词匹配近似段落，或退到裸条号，且只处理前 20 条 claim。新复现中，“无需保存日志”的 claim 会被程序挂到“应核对日志保存范围”的正文上，单靠相同词语不能建立对应。

删除这些近似匹配，只在正文中能唯一定位完整主张（忽略 Markdown 呈现差异）的段落末尾添加小型标记，保留该主张的全部支持来源；同段同来源去重，不逐句堆标记，不再截掉第 20 条以后的关系。

不能唯一定位时不猜位置，原有结构化 claim 与引用关系仍保留，不为定位追加模型调用，也不因无高亮而让报告失败。正式执行器和 Markdown 生成路径使用同一个程序函数。前端沿用已有引用按钮，没有新加元数据面板。

### 4. 调查上下文与阅读衔接

正式审查首次决策也直接收到材料包前 12000 字的原文窗口、版本头和续读位置，与问答的阅读方式对齐；不抽取摘要，不修改冻结填报或事实账本，不自动消耗一次显式读取操作。

已逐字出现在预览中的完整、单片段、具备条款资格的短条文，也在正式审查中登记为本次已取得证据，避免仅为取得引用身份再次读取。截断、多片段条文和参考材料不因此升级。

导航按来源与位置分组，复用问答已有的去重投影：模型不再重复接收相同未变候选，完整原始观察仍保存在审计轨迹，所有既有原文和接口思考仍在原生历史中。没有导航时保持原观察，不新增虚假的空导航字段。

调查次序、工具数量、预算和原有范围策略没有调整，也未增加批量召回数量。

### 5. 相互冲突的旧提示与丢失字段

旧生成路径仍用具体出境法律答案示范结构，包含过时规模表述、“尽量分散引用”、优先代表片段、逐句覆盖及自检 sufficient 时尽量给确定风险等指令。现在使用输出 Schema 说明格式，移除法律答案示例和这些与正式 Agent 原则冲突的要求；根据实际支持关系选择引用，关键事实未知时保留条件和证据不足，正文、摘要与清单保持条件一致。

这是对旧入口已存在的矛盾做对齐，不是把上一轮问答候选当作已验证的新能力。正式 Agent 的主要判断提示继续沿用原有通用原则，仅补充材料窗口、来源选择与程序编号契约。

另复现旧生成器在纯文本和 Markdown 两条路径中都会丢掉草稿的 `legal_path`。现在保存该字段，并与正式执行器一样拒绝“证据不足却填写确定路径”的组合。

## 验证方法和边界

先新增定向复现，再修改代码：最初 6 项检查均失败，覆盖首次材料窗口、两种格式的原文截断、核心报告背景、未用来源展示及错误段落引用。路径字段丢失另在两种格式中复现。测试使用固定原文和 FakeClient，不调用真实模型。

新增及更新覆盖：

- 首个原文窗口与续读位置，不自动写入事实账本。
- 两种报告格式保留完整材料、原文及来源资格。
- 核心/栏目共享全文背景，同时分别维持对象和覆盖要求。
- 交付仅含声明使用的来源，独立核验与审计仍保留全部已取得资料。
- 参考资料保持参考资格，未取得 ID 不能交付，不能用参考身份绕过正式法条门禁。
- 精确且唯一的段落关系、多来源绑定、重复段落不猜测、词语相似不误挂。
- 正式/问答两条检索路径的完整短条文衔接，以及截断、多片段和非正式资料的反向检查。
- 正式工具对话中的导航去重、原始观察与接口思考保留。
- 六次历史提交的离线回放，原稿、退回理由、修订定位与事实来源继续保留。
- 问答不生成正式整改审批，正式审查材料归属、核验拒绝、关键事实缺口与审批回归。

未重建语料、修改 goldenset、调用真实模型或重跑上海任务；未改前端页面，也未做浏览器流程验收。测试证明的是输入、引用与流程契约，不证明正式报告的法律质量提高，也不证明提示整理能稳定消除模型推断错误。

最终验证：后端全量 **879 passed**；前端 **19 项测试通过**，`npm run build` 通过；相关文件 Ruff 与 `git diff --check` 通过。后端全量包含六次历史草稿离线回放及正式核验、材料归属、审批门禁回归。

## 成本说明

保留原生历史和增量上下文，没有人工交接摘要或重新作答阶段。系统提示及 Schema 使用稳定前缀，同源元数据合并，重复导航不再次发送；核心报告背景在单次核验请求中只保留一份。

旧生成路径恢复完整原文后，输入可能比过去的静默截断更多；不能把字符数更少或更多直接解释为最终费用变化。本轮未做真实 token、缓存命中或耗时对照，不宣称成本下降。
