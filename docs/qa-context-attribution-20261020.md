# 问答残留问题：模型、上下文与工具归因

2026-10-20。基于[四题复测](qa-problem-retest-20261020.md)的保存结果、公开checkpoint、原生协议散列审计、当前源码和官方工具文档做离线分析；没有增加模型运行，没有修改生产代码。工具定义重建后的散列与原请求审计一致。量化结果位于`data/review_runs/qa_problem_retest_20261020/context_diagnosis.json`。

**现有证据支持“信息已到达，但当前模型使用不稳定，同时工具仍给了较重且混杂的输入”。尚不能把残留错误定性为模型能力上限，也不能把它们全部归因于缺上下文。**

后续实现与验证见[问答检索上下文与工具Schema精简](qa-search-context-implementation-20261020.md)；以下保留改动前四题的诊断依据。

## 工程侧仍存在的具体问题

### 1. 问答仍携带完整审查事实结构

`QAState.facts`是19字段的`ReviewFacts`。两道HR题直到结束仍全部为空或unknown，但原材料已明确提供CIIO、人数、重要数据及豁免事实。当前提示说它只是检索线索，不应覆盖材料；然而字段名称仍为facts，语义不够直接。这是同一输入中“原始前提明确、结构化投影未知”的设计张力，不能据此声称程序覆盖或删除了原始前提。

还有一个实际操作缺口：HR材料指定2026-10-08，但`as_of_date`始终为空；`ComplianceAgentTools.search`因而按运行日过滤。这次结果未发现晚于10月8日的发布日期或生效日期，未观察到答案因此改变，但历史时点没有落实到检索参数。模型没有提取该可选参数，工具随后使用默认当前日期，两侧需要一起处理，不能用填满事实表的方式解决。

适宜方向是收窄问答工具确实需要的检索线索、澄清其身份，保留用户原话及模型自身连续调查；不新增人工事实总结，也不生成正式事实台账。

### 2. Schema携带过多重复定义

五个原生工具各自包含一份完整`ReviewFacts`定义；工具定义共20,130字符，其中重复事实定义合计13,040字符，约64.8%。首次请求尚无调查法源，输入就约8,300 token。

这是已确认的固定输入负担，不等于已证明它导致法律错误。五个工具并不需要动态工具发现系统，优先精简共享参数和Schema即可，不宜为此引入复杂的新框架。

### 3. 少量来源代表被扩成大量同等呈现的正文

`search`默认选10个来源代表，再加入同源支撑和相邻块；`flatten_source_evidence_packets`将其摊平成证据列表。模型投影移除检索排序等技术字段后，原有代表、支撑、邻接的包结构也未被单独表达。`query_results`及`read_history`仍可辅助追溯，不能说全部关联消失。

敏感信息题包含汽车出境、跨境认证、粤港澳跨境等旁支；欧盟题没有目标法案，检索仍返回一整批中国标准和法规。原文之外还有导航及关联数据，例如首道HR题的一次搜索observation约12,984字符。峰值请求约2.5万—3.8万输入token。

不能把表中片段全部叫作无关，也不能从数量直接推出错误因果。但当前策略确实将较多筛选负担放到回答模型上；尤其库外查询，“排名靠前”不代表足以回答。

改进应控制进入上下文的内容，而保留后台候选和按需精读入口：少量主要原文结合来源导航，其他正文按需读取。反对观点、适用例外和重要相邻条件必须仍可发现；不能简单按长度截断条文，或只保留支持初始结论的片段。

### 4. 来源身份已经传到，但分类不够精确

相关标准保留了`implementation_reference`与不可作为正式法条的资格，不过`doc_type=guideline`、`authority=public_interpretation`与其他资料共用，`law_status=effective`也不意味着强制法律效力。现有元数据足以避免宣称“完全没告诉模型”，但仍不足以细致表达所有来源性质。

应治理真实来源分类，并让工具结果更直接地呈现已有身份；不能凭标题或原文中的“应”新增法定效力判断，也不能把所有不可引用为法条的官方解释都降成可有可无的建议。

### 5. 评测输入和判据也有局限

Judge收到原问题、材料、intake、rubric和最终result；result带所选引文，**没有完整调查证据集合**。所以它把敏感信息题的“信息汇聚”和“审计重点”判为缺支撑，而相应完整原文实际在本轮evidence里。这里是评测可见上下文不足与判词过强，不是原回答凭空编造。最终依据关联仍可改善，但不要求每句都加引用。

用例runner还把旧审查intake作为“用户提供”的文本附件追加，敏感信息题直接包含`sensitive_personal_info=true`。这意味着本次核心定性正确不能当作独立识别能力的纯测量。原材料、业务字段和范围备注也有重复或不同侧重。保留旧基线；未来若清理评测输入，应另建版本，避免悄悄改题后比较分数。

## 其他Agent如何控制无关信息

公开文档能确认API和公开工程实践，不能据此断言ChatGPT、Claude聊天产品的完整内部流程。

- **OpenAI**的[Retrieval文档](https://developers.openai.com/api/docs/guides/retrieval)提供属性过滤、排序器、相关性阈值和混合检索权重；[File search文档](https://developers.openai.com/api/docs/guides/tools-file-search)支持限制返回量，也说明过度减少结果可能损害质量。它们体现的是工具侧预筛选与模型理解结合，而非把全部命中直接交给生成模型。
- **Anthropic**的[上下文工程实践](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)介绍保留轻量标识、按需加载原文的方式，Claude Code结合初始资料与自主搜索；这并非固定拆成调查与作答两个Agent。
- **Claude API网页搜索**的[动态过滤](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)允许模型通过代码先过滤结果再将相关内容带入上下文。说明提前设计与模型判断可结合；不意味着我们必须照搬代码执行或额外增加筛选模型。

对lawAgent，合理分工是：程序负责权限、确定的版本/时点条件、去重及返回规模；检索和重排负责候选相关性；Agent负责选择精读、理解适用条件与例外、发现冲突及继续搜索。目的地是德国不等于适用法域只有德国，不能据此排除中国法；地方题也不能过滤掉适用的全国规则。证据不支持初始结论，仍可能高度相关。

这一设计可以减少成本和干扰，但不是正确性保证。现有RRF排名不是可直接套用某个阈值的概率，不能把OpenAI接口的阈值数字搬过来硬裁；需要用覆盖关键规则及例外的样本校准。

## 先修什么，怎样区分模型限制

优先处理可确认的输入负担和工具缺口：问答Schema与线索身份、历史时点参数、候选/正文的返回组织，以及网页发现连接问题。保持现有原生对话，不手动重写模型思考，不增加问答语义核验器。

随后采用小范围固定对照，分开两个问题：同一模型和预算下比较原工具返回与精简呈现；保持同一非私有输入资料再比较不同模型或推理强度。不能同时改工具、模型和提示，再用改善结果给某一改动归功，也不宜将某模型的私有推理迁给另一个模型。

检查回答是否保留已知/未知区别、是否错误提升标准措施、是否漏掉例外；同时记录关键证据是否实际送达、调查量、输入输出成本和工具失败。模型在干净且完整的输入下仍稳定失败，才有更充分依据讨论能力限制。当前四题没有完成这种对照，因此只可报告当前表现，不能宣布已达到能力上限。
