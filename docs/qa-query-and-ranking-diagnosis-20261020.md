## 查询生成的实际缺口

已确认题第一条原查询将第38、39条、安全评估、标准合同、认证、单独同意堆在同一条里；另外两条分别检索跨境HR免予及影响评估。工具调用的公开summary已经把单独同意表述为“仍须履行”的义务。

这些文本表明搜索围绕一个已预设成立的义务展开，而“为什么在本案需要同意、该义务与HR合法性基础是什么关系”没有变成实际查询。这里是调查问题分解和查询覆盖缺口，不只是某个同义词选得不准。不能从工具summary推断完整私有思考，但实际发出的查询可以核对。

现有主提示已经要求核对合法性基础和例外。继续重复同一句原则，没有证据能解决行动未落实的问题。后续应针对查询行为改进说明与验证：每个查询围绕待解决判断，区分机制、合法性基础与具体义务；未知适用关系不能在操作说明中提前变成确定义务。不增加固定调查顺序或每题必搜条文。

## 字段排序的直接机制证据

现有ES查询对`title^2`、`citation_label^2`、`heading_path`、`text`等字段执行multi_match，没有把文档名称和条号转成文档内定位。实际ES解释结果表明，在所检查条目中，各字段分数取最大值：

- 跨境流动规定第5条的正文分数约33.64，标题分数约54.15，最终按54.15计分。
- 同一法规第1至14条在原HR查询中均为54.15；真正HR豁免所在第5条没有因正文更贴题而领先其余条文。
- 排第一的其他片段由citation_label贡献约57.68，高于第5条的54.15。

这直接说明“命中目标法规名称”和“该段正文回答当前问题”被混在同一评分中。重复的标题、引用标签和目录信息能遮住正文相关性的差异，造成同一来源的宽泛内容占据靠前位置。换成正文消融后关键片段上升，与这一机制一致。

原38/39条查询前10还出现澳门专项合同和关键信息基础设施保护条例的第38条。这些条目不能因为共享条号就被视为目标法律的相应条文。认证规范与标准合同一般资料可能相关但不是本案关键判断，不能把它们全部叫作完全无关；明显不适用的专项来源与相近主题但价值较低的资料应区别处理。

向量召回也没有自动弥补缺口。原义务查询的第13条不在前200；改为合法性基础查询后排第1，说明语义召回同样受到查询所描述关系的影响。不能指望向量检索在查询已经聚焦一般义务时总能补出所有前置规则。

## 调整后的实施优先级

1. **调查查询与工具契约。** 让模型围绕未解决判断生成聚焦查询，避免把多个机制、义务和条号堆成一条搜索。已知来源和条号时使用现有精确读取；主题检索仍保留跨来源发现能力。
2. **正文相关性与来源身份分开处理。** 标题、法名及条号用于定位或适度辅助，正文应能拉开同一法律不同条款的分数。不能仅从消融直接决定新权重，需要用已保存候选和其他题校验。
3. **明确不适用来源粗筛。** 根据用户明确给定的地域、目的地及主体条件限制专项资料；保留全国一般规则，不按照某个法律结论精筛，不重建完整ReviewFacts提示Schema。
4. **再修融合、裁剪及导航。** 避免单路有价值结果被早期截断；使后台存在的其余候选有少量可发现、可续读的位置。保持正文规模受控，不把候选全部交给模型。

前两项处理“有没有找对方向、相关片段能否排上来”，第四项处理“已经找到的内容是否交到模型手里”。不能只通过放大top_k或增加导航掩盖前端排序问题，也不能只改提示而保留已证实会掩盖正文相关性的评分。

应分开验证查询改进与检索配置改进：先固定查询比较排名、关键原文覆盖、专项噪声和输入量；再固定检索配置检查Agent自主查询和最终回答。人工改写及正文消融目前只是诊断证据，不是生产修复或稳定收益证明。
