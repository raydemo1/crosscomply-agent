# 候选导航与批量读取验证

2026-10-30。本轮不修改混合检索、全局正文选择、索引或默认模型配置；摘要仅在实验入口启用。旧答案及轨迹复用缓存，不重新生成。

## 已实现

- 现有候选导航改为每个查询混合检索前八名中的未读位置，不补位；同一位置合并查询归属及查询内排名，来源信息共用。
- 统一使用 `candidate_navigation`，删除旧关键词导航字段。默认预览为原文前100字符，短文本保留；预览不能直接获得引用资格。
- 历史相同预览不重发；只更新查询关联时只发送定位及关联，保留旧预览。已取得完整条文的其他锚点不重复展示，单chunk读取不会把整条标成已读。
- 单批最多四处读取并发执行，预先校验和分配预算，主线程按请求顺序合并结果和检查点。单项失败保留其他成功项，不重复执行同批完全相同的请求。
- 按chunk只返回该片段，不自动添加邻居；条文和章节分页仍保留。并行主要用于批量取证，不声称内存读取获得显著加速。

## 冻结十一题回放

最新十一题中九题使用搜索，另两题直接定位法条。沿用旧来源/条号定位观察点，九题的结果如下：

| 指标 | 旧导航 | 新导航 |
|---|---:|---:|
| 正文命中观察点 | 15/26 | 15/26 |
| 正文加导航发现观察点 | 16/26 | 21/26 |
| 预览原文字符 | 18,797 | 14,007 |
| 序列化完整导航估算token（cl100k） | 29,353 | 28,811 |

预览字符减少25.5%，但完整导航估算token只减少1.8%，因为候选定位和查询归属也占空间。导航发现不算已经取得证据；上述不是证据充分率或QA准确率。

## 实验约定

四题为小量敏感信息、上海清单、HR条件未知、HR文件与同意例外。A为原文前100字，B为预生成主题摘要，C为结合问题和查询的即时主题摘要。每组使用相同读取机制及原生预算，真实查询由模型自主生成，因此跨运行候选可能不同；固定候选比较在离线回放中进行，真实运行用于观察实际效果，不作为固定输入的因果证明。

B在运行前生成实验候选摘要，并校验原文哈希及摘要版本；新规划出现未预生成候选时明确报错，不即时补生成冒充缓存命中。C每次有候选的搜索统一调用一次开发模型。生成缺失、重复ID、超长及传输失败均记录，不静默改用原文预览。

用户已选择A作为当前采用方案，B和C不启用。前四题A已完成：13次请求、197,476 token；缓存旧结果17次、272,063 token，减少27.4%。C四题18次、213,723 token，并有人工原文对照发现的实质性问题。B在用户中断后停止，静态摘要保留100/474条，四题实跑未进行，不据此宣称A优于B。

剩余七题已完成串行测试及14次原模型独立复审，未继续生成摘要。后端源码哈希与前四题A完全一致；七题旧结果只复制缓存、不重新生成。原模型分别做不含答案的检索复审与匿名答案对比，结果不反馈给开发模型。单次筛查不作为稳定准确率。
