## 需要特别警惕的强约束

1. **格式要求不能冒充推理能力。** 当前core_checks要求正文问题必须逐字、唯一定位；claims全部通过但正文退回且未给定位时，post-validation会拒绝。连续重试仍不合规会抛出ReviewWorkflowFailed，run_agent直接向上传播。这可能把一次有用但不够规范的核验意见变成任务失败。路径已由代码确认，实际发生率和成本尚未验证；不应把“拒绝无定位反馈”的测试当作Agent更可靠的证明。
2. **不能靠完整性口号代替调查。** 最新完整问答的上海2025来源只取得封面、说明第一项和第二项，缺少说明第三项；最后没有继续精读。出现相似行业规则文字的其他地区来源不能补作上海原文。此前另一轮已取得上海第三项，却仍将不同分支接在一起，说明证据缺口与表达错误两种情况都存在，不能统一归因于检索。
3. **不应为使上海案通过而写入上海分支、固定清单、必读某块或强制检索次数。** 当前通用实现未发现按上海source_id直接赋结论或自动放宽引用资格的分支；但名单/目录、行业覆盖、一般门槛等提示越来越贴近单案失败模式，尚无其他问答案例的泛化证据。
4. **安全阻断与答案正确是两件事。** 引用有效、缺口阻断和问答隔离有必要，但不能补足行业范围、例外关系等法律推导。

## 后续采用的修复标准

- 有真实失败记录，能指出具体在哪一步违反工具、证据或交付约定，才将其登记为确定性bug。
- 单项修改对应单项预期，不在同一效果比较中同时更换提示、上下文、推理设置和验收规则。
- 免费回放用于证明原文、状态、反馈、边界和错误恢复；其注入答案不能证明模型会自主选择正确动作。
- 真实行为评测沿用冻结问题与法律判断标准，不限定工具路线、输出措辞或固定稿数。阅读完整性任务与法律问答质量任务分开计。
- 对确定性修复保留已建立的回归；对提示、裁剪、推理配置和新核验协议标为待验证，不继续默认堆叠，也不因证据不足就未经授权回滚其他工作。
- 当前不再为上海单案追加多轮付费尝试。后续验证应选跨场景的小范围对照，并在开始前明确要排除哪个失败机制；12条问答与10条正式审查仍为候选集，未发生完整重跑。
