# 问答范围提示分项测试结果（2026-10-21）

## 结论

两项候选均未显示足以进入生产的质量收益：只重申原问题没有消除重复审查；只改范围/完成规则也没有稳定消除错误，部分候选变短但出现额外问题。本轮保留现有生产提示，不因测试过候选就采用它。

实际完成：两条既有题各捕获一次真实调查后的完整最终请求，随后12次固定历史流式作答，以及范围规则从第一轮应用的2次完整QA运行。固定历史作答的12次均完成，两个完整运行均完成。两次捕获止于最终请求发送前，是诊断快照，不是完整问答成功或失败。

协议见`qa-scope-slice-protocol-20261021.md`，数据在`data/review_runs/qa_scope_slices_20261021/`。模型固定`deepseek-flash / low`，无Judge、Oracle、人工交接摘要或失败后重抽样。

## 新发现：此前已有一份答案留在原生历史中

未知题原版真实调查的第3个模型请求，在未调用工具时直接返回2103字符的完整答案。`ToolCallingAgent.decide`要求注册工具，保留该assistant消息后返回“请使用已注册工具；完成调查或提交报告时调用finish”。第4次请求才调用finish，随后程序再发送最终流式请求。

因此，该题固定历史测试的最终请求已经带着一份旧答案和相同的条件推断。原版、重申问题和范围规则的最终输出都非常接近这份先前答案。它为“末尾提示没有扭转既有写法”提供了具体背景，但没有通过删除旧稿或修改工具选择参数来验证因果；本轮没有丢弃历史、替换思考或为此增加生产修订循环。

代码上调查阶段客户端使用`tool_choice=auto`，而运行循环只接受工具调用。这种组合允许模型提前生成正文，再被要求补工具。是否及如何改变工具选择策略，需要独立核对当前DeepSeek接口兼容性，不在本轮未经验证直接改动。

法律推断错误并不是由这份旧稿凭空产生：更早的调查思考已经把问答中的必要、最小化原则解释为制度必须记载具体出境事项，随后写入conditions和旧稿。仅修完成协议不能据此承诺法律判断会变正确。
