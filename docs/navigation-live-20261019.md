## 新导航是否被实际使用

是。两个专项任务使用独立阅读提示，由模型自行选择工具参数；预期文本块 ID 仅用于事后核对，没有放入模型输入。

- **个人信息收集**：浏览来源根目录 → 选中第 5 章节点 → `node_id, offset=0` 取得 5 块 → 使用完整续读参数 `offset=5` 取得 5 块 → `offset=10` 取得 3 块 → 生成摘要。没有提前把第一页当作全文。
- **汽车出境流程**：根目录第一页返回 30 项和 `next_offset=30` → 浏览第二页 25 项 → 选中“三、数据出境流程”节点 → 一次取得对应 4 块 → 生成摘要。
- **完整生产审查**：HR 案采用直接条号精读；上海案采用文本块精读，并浏览了一次新根目录，但没有用章节节点精读。

本批没有实际调用 `parent_node_id` 展开子目录，该分支仍只有此前的无模型测试证据。专项提示与生产审查提示不同，不能由专项成功推断生产 Agent 会在所有案件中自主选用章节导航。

## 实跑暴露的问题

### 1. 上海清单已读到，但核验上下文没有带过去

上海案在第 5 步成功读取 5 块 2025 版负面清单原文，保存于 `state.evidence`。这些块的引用角色为 `conditional_local_basis`，且 `can_cite_clause=false`。

第 8 步提交报告时，第 26 次模型调用的核心核验输入只包含正式引用与 `interpretation_auxiliary`。5 块已读的 2025 清单均未进入输入；核验员因此明确表示“未提供2025版清单原文、发布或备案文件”。代码中的输入筛选条件与实际请求记录一致。

这条证据链定位到**阅读结果向核验上下文传递时的来源角色筛选**，不是没有取得清单原文。它解释了这次核验缺原文的反馈，但不能说明补齐上下文后报告一定会通过，也不能解释所有待补事实。

下一步应优先设计：让已实际阅读、允许用于解释适用范围的条件性地方依据进入核验视野，并明确其资格，继续禁止它越权支撑正式法律 claim。本次没有改动该逻辑。

上海案最终问询行业、数据类别、重要数据/CIIO 身份、出境人数、处理目的及接收方等事实。案例没有预设回答，因此停在 `waiting_input / unanswered_gate`，没有伪造事实补齐或生成确定结论。

### 2. 上游章节路径存在实际串章

《个人信息安全规范》的“5 个人信息的收集”节点覆盖 13 块，其中以下 4 块正文已进入第 6 章存储要求，却仍挂在第 5 章路径下：

- `tc260_gbt_35273_2020_pip_security_spec:1035ea20ab9e7441505ecb25`：个人信息的存储、6.1。
- `tc260_gbt_35273_2020_pip_security_spec:c67d99344224a7f7a5f8de0f`：6.2 去标识化处理。
- `tc260_gbt_35273_2020_pip_security_spec:aa65aeb269db96cdcf761a45`：6.3 个人敏感信息的传输和存储。
- `tc260_gbt_35273_2020_pip_security_spec:9a2d75c0cd8e9396b63d043e`：6.4 个人信息控制者停止运营。

模型在最终回答中主动说明这些是紧随其后的存储要求，并未纳入收集要求的摘要。原文块与路径核对确认了串章现象，但这一次正确识别不保证未来每次都会纠正。

因此，13/13 只证明读全了**现有路径定义的目标集合**，不能证明该节点恰好对应正确的法律/标准章节边界。本轮依既定范围没有修复解析器、重建语料或索引。

### 3. 完整报告的核验与修订成本高于导航操作

HR 案主动精读了个保法第十三条、第十七条、第五十六条，未出现工具读取错误。首稿误引个保法第十条，第一次被核验退回；修订稿的敏感信息假设变化表述仍被判定依据不足，第二次被退回。第三次提交交付并获自动 Judge 通过。

这次成功说明当前模型有完成该任务的能力，但没有证明旧错误稳定消除，更不能归因于章节导航——本案只用了条号读取。344.3 秒为完整执行与评分用时，包含多轮核验，不是一次导航延迟。

上海案另有两次文本块 ID 被截短，实际工具拒绝后模型用完整 ID 恢复；两次窗口内重复读取在预检查阶段被拒绝。`reads=6` 包括 2 次实际失败调用、4 次成功调用；另 2 次重复预检查拒绝不计读取预算。现有结果中的 `duplicate_read_denials=0` 未识别批量观察，分析使用原始 `read_results` 独立计数，没有据此声称不存在重复读取。

## 证据与复现

结构化摘要、核验退回原因及原始产物散列见 [试跑数据](fixtures/navigation_live_20261019.json)。原始产物位于 `data/review_runs/navigation_live_20261019/`：

- `manifest.json`：冻结模型配置、生产文件和语料散列、输入与目标；模型 HTTP 请求总上限 80 次，实际 36 次。
- `model_calls.jsonl`：每次请求开始、最终响应内容、usage 和耗时；不记录 API Key，也不保存模型推理正文。
- 各任务目录的 `events.jsonl`、`state.json`、`result.json`：逐步轨迹、checkpoint、结果；HR 案另有 `payload.json`、`judge_input.json`。
- `run.py`：本次隔离驱动，复用生产运行器与读取工具，增加调用量记录，不修改生产提示和实现。

原目录禁止覆盖。需要复现时，将 `run.py` 复制到一个新的运行目录，在仓库根目录设置 `$env:PYTHONPATH='.'` 后执行。脚本会调用真实模型并收费；它固定跑上述四项，非全量回归。

后续优先处理核验上下文漏传和已确认的串章，再决定是否需要新的模型试验。当前没有证据支持因此替换混合检索或引入 PageIndex。
