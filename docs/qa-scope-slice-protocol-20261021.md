# 问答范围控制分项对照协议

## 第一项：作答前重申用户原始问题

固定两条既有候选：`agent_hr_exception_missing_001`、`eval_standard_contract_003`。各做一次现有生产调查，在最终流式请求发送前捕获全部原生消息、模型此前返回的思考、工具定义、引用表与来源原文，不人工生成交接摘要。

对同一捕获请求，原版与候选各执行两次。候选仅在最后的完成控制中加入逐字的`user_question`；保持此前全部消息、system提示、材料、来源、引用编号、思考强度及流式参数不变。顺序第一遍原版→候选，第二遍候选→原版。共8次最终作答，没有Judge、答案Oracle或失败后重抽样。

## 判读标准

先看最终正文，DeepSeek返回思考用于解释观察，不以其自称遵守代替答案检查。

1. 已知前提：把已明确的HR必要性、劳动规章制度或集体合同重新要求核查、举证，记为重复审查。归因清楚地沿用前提、解释法条本身条件不记错。
2. 附加门槛：只有原文支持才可把合同具体记载内容、覆盖接收方或数据字段设为法定前提。可选留档建议与强制文件要求分别记录。
3. 未知分支：集体合同未知不等于没有，不可据未知直接确定安全评估必然适用。允许解释条件不成立时的后果。
4. 义务与例外：如展开告知、同意等剩余义务，不可无条件要求一律单独同意而忽略已给原文中的例外。没有展开可选事项与明确解释例外分开记录，不因省略所有细节直接判为掌握例外。
5. 任务范围：未知题聚焦是否适用机制；已知题原始问题询问文件和备案，材料又明确要求区分出境机制与剩余义务，不能把所有文件说明都判为偏题。重申原问题不能覆盖附件中的明确补充要求。
6. 核心交付与引用：判断条件、机制后果、有效编号及来源关联应保留，不能用短答掩盖必要解释缺失。可选建议不得升级为正式整改或审批动作。

两次重复只能提供探索信号，不给稳定准确率或显著性结论；工具历史固定，比较仅评价最终作答，不证明调查效率改善。
