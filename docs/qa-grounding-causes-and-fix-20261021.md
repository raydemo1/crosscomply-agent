# 问答事实适用错误：原因对照与修复

日期：2026-10-21。

## 结论与实际交付

本轮没有找到可以稳定修复两类正文错误的提示或配置变更，因此没有替换生产提示、清空原生调查历史、提高生产思考档位或增加语义核验模型。

已修复一个独立、可复现的程序缺陷：模型写成 `[ [cite:原有ID] ]` 时，旧解析器既没有转换引用，也没有阻止内部标记进入答案。现在解析引用分隔符时允许空白，ID 仍必须与本轮实际可用来源精确匹配；不猜来源、不纠正 ID 拼写、不修改正文判断。真实记录回放中，该回答从漏识别全部引用恢复到正确关联 17 条引用记录（不等于 17 份文件）。原有 5 份含未知 ID 的响应仍被拒绝。

正文问题的判断是：**当前 DeepSeek Flash 配置存在事实与法律条件对应不稳定的问题，不能再把它全部归为检索缺失；但本轮不足以证明模型的绝对能力上限。** 推荐性标准问题也不是完全不会区分，而是清单、附带义务或末尾总结中的资格限定会发生丢失。

## 固定输入和执行边界

两题：`eval_cross_border_001`、`eval_sensitive_002`。问题、材料及评分要求与之前保存的试验一致。

- 出境题：材料只说明“日均处理约50万用户”，没有确定年度累计出境去重人数，也没有确定定位是否形成轨迹。
- 敏感信息题：材料明确持续精确定位及到店记录、用于优惠推荐和广告、暂不出境；目标检查推荐性标准是否被写成确定法定义务。

使用 `qa_general_reasoning_20261021/live` 保存的 baseline 末次真实请求，保留当时的工具定义和原始资料身份。该前缀来自此前失败运行，**不是本轮完整重新运行检索后的请求**。同模型别名 `deepseek-flash`，除 high 组外使用 low。所有探针统一 8192 输出 token 实验上限，不修改生产预算；没有收到 length 截断结果。

共 32 次真实模型请求：20 次前缀对照、8 次固定资料作答、4 次提示候选。没有新增完整 worker 评测，也没有独立 Judge。此处人工复核针对上述两类错误，不是整体法律正确性评分，未改写旧评测分数。

## 第一阶段：20 次失败前缀对照

五组各两题、每题两次，顺序轮转。除了列出的变量，其余保持相同。

| 组别 | 唯一主要变化 | 出境题 | 敏感信息题 |
|---|---|---|---|
| native_low | 原样前缀 | 两次均存在无依据的高概率结论或处理量到累计出境量的推断 | 一次目标通过；一次正文有标准限定，但结尾合列义务，记为边界表达弱 |
| raw_inputs_tail | 最后一条程序消息再带入原问题、原始材料片段及版本、偏移；不作摘要 | 两次未消除上述错误 | 两次在目标问题上区分了标准来源；基线也已有能正确区分的回答 |
| fresh_same_evidence | 移除调查历史，仍提供全部已取得原文、原提示、工具及来源资格 | 一次继续检索；一次正文仍错 | 一次只调用 finish；一次 finish 带正文，标准专项要求与内部管理措施并入义务 |
| native_high | 只提高思考档位 | 两次未消除上述错误 | 一次目标通过；一次部分标准要求的层级表达仍不清楚 |
| oracle_subset | 在 fresh 基础上，仅保留既有证据的直接相关规则 | 两次均继续工具调查，没有正文 | 两次均继续工具调查，没有正文 |

其中 6 次完全没有正文，不能算法律判断错误，也不能算 Oracle 答对。另外 3 次正文与 finish 同时返回，其正文可以检查，但未执行本轮探针返回的工具调用，不能视为完整 worker 成功。

引用与内容单独记录：第一阶段 5 份响应存在未知来源标记；另有 1 份全部采用带空白的标记，旧解析器未识别。不能把“没有抛异常”当成引用已正常交付。

## 第二阶段：8 次固定资料作答

第一阶段 Oracle 只选择继续调查，未实际测到作答能力。因此在查看其结果后另行冻结第二阶段方案：两题 × 全部已取得原文 / 直接相关原文 × 两次，均不带调查历史，保持相同原系统提示、工具定义、low 及输出上限，追加同一停止调查指令，使用 `tool_choice=none` 并保留工具定义。

这个阶段内比较的是证据集合，不与第一阶段直接混合算通过率或速度收益。它也不能分别归因于停止调查、去除历史或接口处理。

| 题目 | 全部已取得原文 | 直接相关原文 |
|---|---|---|
| 出境 | 两次均错；正文知道累计出境口径，仍以处理规模推高概率申报 | 两次均错，且出现定位直接等同行踪轨迹、日均规模直接推出超阈值 |
| 敏感信息 | 两次明确区分法定义务和标准参考措施 | 一次混入直接义务，一次正确区分 |

Oracle 不是人工提供正确答案，也不是补齐全部法律调查。它仅从既有原文中保留直接相关内容；缺少的原文应促使回答限定结论，而不是自行补造事实。结果说明：**降低资料量没有单调收益，不能以更少资料就更准确为依据改生产裁剪。**

## 第三阶段：4 次原句锚定提示候选

仅替换生产提示中的一个作答组织段落：先根据决定性的用户/材料原句对应规则，再组织结论与分支。原问题、全部原生历史、资料、工具、low、auto 及输出上限不变；不增加总结交接、核验模型或第二次改写。

两题各两次。敏感信息题两次在目标问题上区分了参考措施；出境题两次仍写“很可能已经需要申报”，并根据日均规模断言累计去重人数很快超过门槛。一次还含未知引用标记。

候选没有达到预先记录的采用条件，**不进入生产，不扩大完整运行试验，不继续堆叠提示**。

## 对原因的进一步判断

1. **不仅是没看到法条。** 原始前缀和固定资料组均实际包含申报门槛原文。多份正文能先正确解释处理量与出境量不同，随后仍推出相反的高概率判断。这是事实到规则条件的对应错误。
2. **错误在生成响应时已经发生。** 查看保存的 provider reasoning_content，能看到其将处理体量当成出境超量的推断方向；程序没有把正确正文改成错误正文。思考内容只用于定位发生环节，不作为判断正确性的证据，也不对用户展示。
3. **历史不是充分解释。** 移除历史后仍可出现同类错误，不能把清空原生思考当修复。重新放入原话也没有稳定收益。
4. **资料数量也不是充分解释。** Oracle 仍错；敏感信息题保留更多资料反而两次都能交代标准性质。不能凭两题确定统一最优资料量。
5. **提高思考档位没有解决。** 本轮不能证明当前模型在所有设置下都做不到，只能说明 high 不是这两题的现成修复。
6. **标准错误需要按完整语义判断。** 明确说“推荐性标准提出应……”本身不等于冒充法律义务；前文限定可关联后文。没有明确关联而把标准措施列为直接法律后果，才记为目标错误。边界弱与明确错误分别保留，没有为了增加错误数量重新定义 rubric。

目前应保留“当前配置的模型判断不稳定”这一结论。要进一步认定是否值得换模型，应固定同一批问题、原始材料和原文，对不同模型做小范围重复对照；本轮没有默认更换模型或调用其他供应商。继续加禁令、挑选最好回答，无法支持更可靠的产品判断。
