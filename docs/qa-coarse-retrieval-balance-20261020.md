# 问答检索：恢复适量正文，只做保守粗筛

2026-10-20。本轮删除“每查询只交付一项主要正文，其余全部变导航”的问答实现。继续保留上一轮工具Schema精简，避免把两个问题捆绑回退。目标是直接给出有上下文的相关资料，由Agent判断适用关系，而不是让每个命中都再经过一次主动读取。

## 实现范围

- 复用现有混合检索、来源融合与来源证据组。主要正文、同源支持片段及相邻条件直接进入调查上下文；保留既有top_k和证据组限制，不返回整个语料库。
- 问答仅对明确不匹配的地方规则、行业规则做程序粗筛。复用已有地区和行业元数据；全国规则、一般法律、解释辅助及未知范围不据此删除。境外接收地不被当成唯一适用法域，省市范围有交集则保留。
- 用户原问题或当轮查询明确提及的比较地区、行业、完整来源名称优先保留。仅有主题标签不构成行业排除依据。原问题保留及标签边界在真实试跑结束后补充并由定向用例验证。
- 不新增模型精筛、相关性阈值、固定法条名单或案例特判。粗筛无法保证返回的每项资料都相关，适用判断仍由Agent结合原文完成。
- 未交付正文的少量关键词候选继续供导航，每查询最多四个位置，按来源合并。取消把全部未交付正文转成导航；模型已取得的正文、历史中相同的导航位置不重复发送，预览或标题发生变化时仍更新。
- 完整原始工具观察仍保存于运行记录。模型对话保留原始用户输入、工具消息与原生推理消息，不人为总结或重建推理上下文。已有正文不要求为取得引用资格再读一次；只有导航预览的内容仍必须取得正文后才能引用。
- 精简后的地区、行业、时点Schema继续仅用于问答搜索。正式审查默认搜索路径、核验、事实确认和审批要求不变；问答不增加核验或审查循环。

### 首题交付失败，原Judge误放行

第一题最后一次流式请求在`delta.content`内返回了以`<｜｜DSML｜｜ calls>`开头的原始`finish`工具调用，没有给出正常答复。它并非SSE中的`delta.tool_calls`，因此已有的工具调用检查没有捕获；原评测只检查非空正文、引用身份及问答字段，也错误通过。Judge把工具参数里的摘要当作答复进行了法律评分。

原始结果和Judge分数完整保留，不将其算成有效回答，更不能据其较短输出或较低耗时宣布优化成功。`delivery_contract_recheck.json`使用新增程序检查复核保存结果：第一题交付契约失败，第二题通过；这不是重新运行Agent或重新法律评分。

运行结束后补了两处处理：

1. 成功结束调查的工具结果明确要求下一条直接给用户Markdown回答，不继续调用工具。
2. 回答流检测实际观察到的DSML开头。前缀跨多个片段时暂缓发布，一旦确认即按执行失败处理；不清洗、解析工具参数来冒充答案，不追加模型调用或自动重跑。评测也增加相同的确定性检查，契约失败不再交给Judge评分。

这些改动通过模拟流和保存的异常输出验证了检测与失败处理，尚未真实复测模型是否仍会产生该格式。

### 第二题的答复观察

正常生成了带引用的条件性回答，未把集体合同“未确认”直接当成“未签订”，分别描述了条件成立与不成立的机制分支。六个已选引用均在正文使用，引用编号和材料归属检查通过，产品调用只有问答调查和问答作答阶段。

但答复仍较长，加入了额外义务和合同内容核对说明；不能因为Judge通过，就认定这些解释均已充分支持或达到人工法律验收。本轮未据此增加法条硬编码或进一步收紧提示。
