# QA 信息身份修复后的单轮真实验证

结论：信息身份按当前契约进入请求，模型能够使用用户更正，但没有证明法律回答整体稳定。人数推测、重复核查已确认前提、无依据扩张仍可见。本轮不继续调整提示或补抽答案。

## 冻结范围

DeepSeek Flash / low，三个场景各执行一次当前完整 QA，不换模型、无独立核验、无 Judge。真实受控库检索和原文读取，未注入固定法条、参考答案或评分规则。公开搜索工具可用，本次模型未使用。

- 人数未知：复用 `qa_deepseek_questions_20261022` 已保存的真实 ask_user 输出和原始材料，以当前表单格式构造“不清楚”的评测答复。原追问不重跑；答复是评测场景输入，不是生产用户新增陈述。
- HR 更正：复用 `navigation_fact_retest_20261022` 的真实 QA 对话，新增“依法签订集体合同已经确认”的评测更正，其他已确认前提不变。
- 标准及合同：复用 `qa_model_context_diagnostic_20261022_completed/cases.json` 中 `eval_sensitive_002_counterpart`，包含已生效服务合同中的持续提示及最小频率条款。

第一题是实际历史追问输出的继续执行，第二题是已有实际问答的继续执行，第三题是已有案例的独立新轮。历史模型回答没有另行伪造；前两题各一轮历史，未用付费模型构造超过八轮的长对话。长历史不截断仍只有上一轮程序回归证据。

这是当前候选检查，没有同期旧版 A/B，场景和前次完整重跑不完全相同。不得归因为本次改动带来的因果收益，不报告法律准确率。

## 输入检查与判读边界

真实首个请求中：三题的 state.goal 均逐字保留评测用户输入；人数题 history 中单独包含 previous_model_questions，用户答复含“用户选择：不清楚”；HR 原回答仍以 previous_model_answer 保留，当前更正进入新轮 goal。可确认信息按预期传递，不能确认模型始终正确使用这些信息。

人数题首段对未知作出了正确限制，后文却重新引入人数概率推测，说明错误至少能够发生在输入已经明确后的回答生成中。HR 能接受更正，仍过度延伸核查；标准题能识别来源层级，仍在后文扩张。不能把这些错误继续统一归结为字段缺失，也没有证据支持再加一轮改写或通用提醒。

保留上轮信息传递修复；不新增法律推理机制。法律内容为候选人工检查，未经过法律专业审定；不宣布三题已修复，更不能宣称长期稳定性提升。若继续优化，应先找到新的具体传递/执行错误；当前这三题没有提供新的确定性工程修复候选。

全部原始请求、输出、费用、输入散列及逐题原句保存在 `data/review_runs/qa_harness_identity_live_20261022/`，入口 `run.py` 拒绝覆盖现有 manifest。`manual_review.json` 记录问题原句和证据边界，`completion.json` 记录调用及成本。后续没有为本轮结果修改生产代码。
