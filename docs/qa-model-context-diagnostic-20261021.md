10月22日已完成16份固定证据回答和4次历史回放，最终结果见[完成报告](qa-model-context-results-20261022.md)。下文保留此前的中断与传输诊断过程；最终决定为不切换默认模型，不触发未满足门槛的留出题阶段。

## 10月22日补充：复现超时机制并修复诊断接收

用户指出未见扣费后，进行了3次额外传输诊断，未恢复整批质量评测。两个最小流式请求分别沿用HTTP代理、绕过显式HTTP代理，都在约4秒内返回OK；相同长输入只改为流式接收，则完整成功：

| 阶段 | 从发送起计时 |
| --- | ---: |
| HTTP 200及首段推理 | 1.469秒 |
| 首段正文 | 100.547秒 |
| 完整结束 | 127.328秒 |

服务端返回输入29068 token、输出5567 token，其中推理4094 token；缓存命中29056个输入token。请求追踪ID为`cfe9d7fc-61e1-45fd-a909-8513018c6aac`。

这复现了能够解释此前失败的机制：诊断客户端此前采用非流式接收并在120秒超时，而该负载生成完整结果需要约127秒。不是因为原文或密钥完全不可用。不能把这次成功倒推为所有旧超时具有完全相同的耗时与原因，也不能把客户端未收到usage或用户未见扣费等同于服务端没有接收请求。

此前缺少响应头及首段数据记录，是诊断实现的缺口。现已仅在评测客户端中改为SSE接收：连接/数据空闲超时30秒，独立总时限300秒；记录响应头、首事件、首推理、首正文、错误阶段及请求追踪ID。复用现有httpx/anyio依赖，保持模型参数、原文、预算及引用处理不变，不增加网络重试或JSON降级；正文、工具参数、原生思考及usage均在完整结束后组装。流中断、截断或缺少DONE不作为成功，未取得用量仍保留费用预留。生产客户端未改。

代理检查只证明绕过显式HTTP代理的最小请求也成功。DNS仍解析为`198.18.0.205`，可能经过透明代理/TUN，不能宣称完成了物理直连对照；未修改代理配置。

原始记录位于`data/review_runs/qa_transport_probe_20261022/`。三次诊断延续原30元总预算，总占用约11.52元，仍包含此前未知用量的保守预留，并非实际扣费。这次传输诊断改变了接收协议及观察时长，不能把返回的法律答案填入旧版冻结比较或宣称模型质量提高。

修复后相关测试44项通过，Ruff通过，覆盖HTTP错误不重试及密钥脱敏、SSE工具参数分片、思考与usage保留、首段时间记录、断流/截断拒绝、总时限取消及原生问答回归。后续模型对照应使用新协议重新冻结，沿用已有成功答案前须明确其传输条件差异；本次没有自动扩跑。

## 当前结果与停止原因

用户随后要求更换密钥重试。新建`qa_model_context_diagnostic_20261021_key2/`，保留原四份基线，仅对同一道规模未知题追加一次候选请求；题目、证据、模型、参数及120秒超时均不变。该次仍在120328毫秒后返回客户端`TimeoutError`，未取得正文。没有继续其他付费请求。结果只能说明本次单独更换密钥没有恢复交付，不能确定排队、网络、服务端计算或接收方式中的具体原因。密钥未写入证据文件。

用户确认充值后，已显式创建恢复批次`qa_model_context_diagnostic_20261021_funded/`。四份已完成的基线答案逐字复用，没有重跑；旧批次的费用占用也带入同一个30元预算。恢复后，GLM在规模未知题及其人数明确的对应题上均等待120秒后超时，没有取得正文；第三个候选请求在停止批次时中断。由于完整交付门禁已不可能通过且不允许补抽，停止其他付费调用，没有继续历史回放或留出题。

**最新阻碍是候选长输入请求未在120秒内完成，不再是已确认的充值问题。** 这不证明模型法律判断较差，也不能区分排队、推理速度、网络或非流式接收方式的影响。本轮不再通过延长超时、缩减原文或重抽答案追求通过；改变这些条件应另立实验，不能冒充原对照结果。

恢复关系、复用答案与旧清单散列均记录在`resume.json`。最终实现增加了`prepare --resume-from OLD_OUTPUT`，只接续明确停止的批次；案例、请求、配置、留出题散列必须相同，成功答案保留，失败与中断记录留在原目录。恢复授权来自用户明确告知已充值并继续当前任务。

**本轮未完成模型比较，不能判断 GLM 是否优于现有模型，也不能据此采用任何提示或检索简化。**

| 项目 | 计划 | 实际 |
| --- | ---: | --- |
| 固定证据作答 | 8题 × 2模型，共16份答案 | 4份 DeepSeek 回答；首批4次GLM 402及1次基线中断；充值后2次GLM超时及1次候选中断 |
| 原生历史回放 | 4次 | 0次，保留冻结数据 |
| 完整留出题 | 满足门禁后8次 | 0次，未满足门禁 |
| 最小协议请求 | 1次 | 成功；GLM返回符合strict约束的echo工具参数 |

模型目录确实包含 `zai-org/GLM-5.3`，最小协议请求也成功；正式证据请求却均返回 HTTP 402。这只能证明当前调用受到接口拒绝，不能据状态码确定账户余额不足、模型无能力或上下文超限。旧余额查询接口返回410；官方公告说明该接口已停用。

初版批处理逐题记录接口失败，却未立即停止整批，因此出现4次失败请求。发现后终止进程，保留一个已发送但未取得返回的请求，不重发。随后先补上HTTP失败停止整批，恢复批次后又将停止条件明确扩大到任何交付失败，包括超时、截断及引用失败。门禁要求完整交付，交付失败已使当前批次无法进入完整QA，不再继续凑齐表格。停止逻辑只用定向测试验证，未为测试该逻辑再次付费调用。

两批证据分别保存在 `data/review_runs/qa_model_context_diagnostic_20261021/`及`data/review_runs/qa_model_context_diagnostic_20261021_funded/`。各自的`manifest.json`仍保留开始运行时的真实源码散列；停止后仅改诊断实现，差异记录在`implementation_after_stop.json`，未把旧清单改成新代码版本。当前代码会拒绝在源码漂移后直接继续旧批次。

## 已实现的入口与边界

入口：`python -m scripts.diagnose_qa PHASE --output OUTPUT`。

| 阶段 | 行为 |
| --- | --- |
| `prepare` | 创建新目录，冻结源码、语料、提示、来源、样本、工具历史、模型配置和预定规则；拒绝覆盖 |
| `protocol` | 一次带strict工具的最小候选请求；失败不降级 |
| `fixed` | 交错模型顺序，八题各一次；干净输入只含问题、材料和完整已取得证据，不含rubric |
| `history` | 四份原生调查历史各回放一次，仅使用原模型；保留工具定义，限定直接作答 |
| `gate` | 检查逐题人工判读及其结果散列；默认空判读不能放行 |
| `live` | 只有筛选门禁通过，才在实际QAWorker上运行四道留出题、每模型一次 |
| `report` | 不调用模型，汇总费用、用量、交付错误、延迟范围及源码变化 |

候选密钥只从进程环境`SILICONFLOW_API_KEY`读取，基线沿用现有环境配置；请求和结果不写Authorization或密钥。没有修改`.env`。

诊断客户端分别构造DeepSeek与硅基流动请求。GLM使用`enable_thinking`及`thinking_budget`，不继承DeepSeek的`thinking`、`reasoning_effort`或Beta路由；strict工具参数原样保留，失败不切成非strict。两端诊断请求都采用非流式HTTP，生产流式交付保持原样。因此诊断耗时不能直接宣称为产品流式体验的提升。

请求前以输入UTF-8字节数、序列化余量和最大输出预留费用；预算为人民币30元。不计缓存和低谷优惠。每个请求身份仅能预留一次；缺用量、失败或中断保留完整预留，防止漏计费用和自动重抽。源文件、样本、来源、提示或模型配置漂移均阻止后续执行。

## 样本与判读

四道原题覆盖规模推定、HR特别免予、标准参考性质和已知前提；分别增加一个改变关键事实的对应样本，共八题。对应样本中的更正作为本轮用户最新陈述，明确标为模拟诊断输入，不声称现实事实已经核实。

原题使用此前实际调查得到的**全部已取得证据**，不补Oracle法条。原题rubric保留，对应样本记录预期判断边界，但这些字段不进入模型请求。四道新场景在输出产生前冻结为留出题；它们与历史题仍有法律主题重叠，不能称为独立专业测评集。

历史中规模题和敏感信息题的主提示匹配当前版本，另外两题不匹配；即便提示匹配，历史回放与干净输入仍同时改变消息组织、工具定义及中间判断，只能作上下文影响观察，不是单因素因果证明。本轮历史尚未运行。

人工筛选要求：八题完整交付，候选目标错误至少比基线少2题；逐对确认没有新增影响结论或义务的错误。每份判读绑定结果散列，错误原句必须出现在答案中，并记录原文依据与理由。即使两版都有错误，也须单独判断候选是否增加了另一种实质错误。未经专业审定，全部保持candidate身份。

本轮四份基线的定向复核：

| 样本 | 目标观察 | 证据与限制 |
| --- | --- | --- |
| 日均50万、实际出境量未知 | 仍有目标错误 | 开头写“很可能已经需要走数据出境安全评估申报”；后文承认人数未知，未约束开头结论 |
| 实际出境量明确的对应样本 | 目标判断成立，非整题通过 | 根据明确人数判断机制；附加解释仍把定位信息笼统等同行踪轨迹 |
| HR集体合同未知 | 仍有目标错误 | 将“未签订或无法确认”合并，随后给出确定申报后果 |
| HR集体合同已确认的对应样本 | 目标错误未出现 | 保持特别免予与一般门槛关系，并解释同意例外；单次表现不能证明稳定解决 |

引用原句及逐项理由见`reviews.json`。无模型回答的402记录保持不可判，不当作法律答错，也不填成通过。没有调用额外Judge。

## 成本与后续决定

两批共13次已发请求：1次协议、4次完成的基线、4次402、2次超时、2次中断。完整返回用量的5次请求，按保守费率估算上限约 **0.39元**；其余请求仍占预留，两批账本总占用约 **9.73元**。预留不是平台实际扣费；不能把超时或客户端终止当作服务端停止计算或零扣费。

四次完成的基线累计输入102375 token、输出7863 token，缓存命中5376 token；单次HTTP耗时约7.4—13.9秒。失败请求的短耗时不能作为候选速度优势。未触发或评估生产引用补丁，不能据此判断它的净收益。

| 能力 | 本轮决定 |
| --- | --- |
| 原生工具、全文阅读、版本和来源资格、确定性引用标记 | 保留 |
| 重复判断提示、QA范围排除能力 | 仍是简化候选；本轮无采用证据，不改生产 |
| 一次引用模型补丁 | 保持当前实现；净收益尚未评估 |
| 新增核验器、答案重写、扩大召回、换生产模型 | 不采用 |

当前结果不足以进入留出题，也没有必要为了凑齐表格继续支付基线和历史回放费用。下一次比较应先单独确定候选的长输入服务交付条件，再预先冻结超时、输出与传输协议；不能将本次没有答案的候选评为法律判断失败，也不能据此修改生产QA。
