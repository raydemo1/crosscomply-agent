本页是目录配对实验后的修复记录。[配对实验](navigation-paired-live-20261019.md)及更早的报告均为冻结历史结果，不因本次修复改分。结构化发布记录和核验结果见 [navigation_bugfixes_20261019.json](fixtures/navigation_bugfixes_20261019.json)。

## 修复范围

### 数字行截断行业父节点

分块器把中文大章节内的阿拉伯数字标题、表格片段按一级标题处理，导致“100 万人以上……”等行截断行业父路径。现在保留其在中文章节内的层级；数字主导的标准文档仍按自身编号层级处理，纯编号 Markdown 标题也按编号确定深度。分块版本更新为 `legal-structure-v4`。

短块合并另有跨章节问题：某个短标题无法并入后文时，会被追加到上一章节。现在向后合并只能进入同一路径或后代路径，向前合并只能在同一路径内进行，防止新行业标题被吞入旧行业。

### 当前语料与双检索存储

先对北京汽车业、银行业及汽车指引做保留逐块正文的路径发布，共修正 16 + 55 块路径、全部复用 160 个已有向量。原库文件、来源清单和知识库状态均事先备份。

进一步核对确认，北京原第 56 块末尾的“七、自动驾驶行业（智能网联汽车）”属于下一行业。根据本轮允许修复文本块边界的授权，将该标题原样移动到第 57 块开头，再恢复整份北京清单的行业父路径。只有两块文本发生边界调整，按顺序拼接后的整份来源文本**逐字不变**，没有添加、删改法定要求。该次发布 89 块复用向量，仅 2 块重新嵌入。

最终父节点覆盖：北京汽车业 8 块、银行业 12 块、医疗器械 10 块、自动驾驶行业 11 块；汽车指引出境流程和安全保护各 4 块。没有宣称所有表格片段标题的语义均已校正。

通过既有 stage → verify → activate 流程发布；正文、路径、引用标签及引用资格已逐项核对文件、ES 和 PostgreSQL 三方一致。全库仍为 63 个来源、1,832 块，其他 61 个来源完全不变，引用资格不变。来源内容或结构变化导致旧节点 ID 失效属于预期行为；旧证据日志保留，不能将旧 ID 自动映射成新证据。

修复工具为 [repair_navigation_headings.py](../scripts/repair_navigation_headings.py)，默认只预览，显式 `--execute` 才发布；可限制块范围，也可显式移动某块末尾的一级标题。预览冻结、源文拼接一致、缓存额度、稳定 ID、资格和其他来源检查均为执行前后约束。发布产物在 `data/review_runs/navigation_bugfix_scoped_20261019/`、`navigation_boundary_fix_20261019/`。语料遵循既有忽略规则，仓库保存修复工具及发布审计，不提交向量缓存或整份运行日志。

### 条件报告与确定路径

- `legal_path` 明确限定为事实与法源支持的个案确定路径；条件分支流程应写正文，不能以流程占据该字段。
- Agent 和独立核验指令明确：本次目标因关键事实不足而不能确定时使用 `insufficient_evidence`；范围外信息不阻塞已有依据的限定判断，不填入本次缺失事实。
- 核验器若同时返回 supported、路径所需缺失事实和非空 legal_path，程序将状态降为 uncertain，不接受相互矛盾的核验输出。
- `evidence_self_check` 不再仅按风险标签生成。最终报告或核验中仍有本次待核事实时，返回 insufficient，并保留 critical_facts_missing 问题和具体原因；没有通过自动修改风险标签让历史评测通过。
- 栏目核验要求强制义务的适用条件和例外保留在本句中，不能靠相邻条目或核验理由自行补足后判 supported。
