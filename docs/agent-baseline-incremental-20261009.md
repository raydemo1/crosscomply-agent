## 主要bad cases

### 同意义务例外遗漏，并被judge放过

HR正例已确认依法制定的劳动规章制度、依法签订的集体合同以及HR必要性。报告仍写：“无论走哪条路径，均须依《个人信息保护法》第三十九条履行告知并取得单独同意。”该题已有禁止判断和必要例外约束，要求区分第十三条的非同意处理依据；并非运行后临时增加扣分项。

[《个人信息保护法》第十三条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)规定相应非同意处理依据；[网信办2026年7月问答第一问](https://www.cac.gov.cn/2026-07/24/c_1786638883119336.htm)进一步明确，符合第十三条第一款第二至七项的个人信息出境活动不需要取得个人同意，但仍应履行出境告知义务。报告不能把告知、影响评估等剩余义务与单独同意一概捆绑。

原始judge已经指出该遗漏，却将法律、例外、事实三项仅标为`minor_issue`，总评仍为PASS。这是同模型judge的漏判证据。离线复核将HR正例记为“违反现有rubric”，保留原始评分，不伪造人工专家成绩。HR要件不足案也在条件成立分支中复现了同一法律问题，但其现有rubric只重点检查机制收口，须与已有rubric违反分开记录。

### 条件变化后的法律分支不够严谨

- HR正例称人数达到100万人以上就须申报安全评估，没有说明该结论需要HR免予等例外不再成立。[2024规定第七条第二款](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)保留第三至六条例外；不能仅凭人数变化推翻仍成立的例外。
- 境外数据回传案称后续“引入境内个人信息或重要数据”时，按80万人考虑标准合同或认证。引入重要数据与引入普通个人信息会改变不同决定性前提，不能合并为同一人数分支；该规定第七条对重要数据另有安全评估要求。
- 酒店预订案在“须同时成立”的前提中列入不含敏感个人信息，但该规定第五条第一项未以不含敏感个人信息为免予前提；敏感信息的保护义务需要另行判断。当前事实确实没有敏感信息，主机制未错，错误在于将案情事实提升成普遍必要条件。

上述问题均来自Agent对法律条件的组织与表述，不宜通过`if count > X`或按case ID补生产规则解决。下一步可引导Agent在写后续分支时重新核对决定性事实、独立例外和剩余义务，不只复述数量区间。

## 2026-10-10 原因定位与修复

HR正例的原checkpoint只返回了个保法第三十八、三十九条，没有第十三条。生产语义校验将“第三十九条转述准确”作为支持无条件单独同意义务的理由，未检查一般处理依据与例外；后续建议和边界也没有得到同等严格的个案推理核对。现已引导Agent分别核对处理基础、出境机制和剩余义务，在事实变化分支中保留未改变的前提，不将案情事实提升为法定条件。Verifier明确核查`legal_path`、建议及边界中的断言，证据缺少相关例外依据时反馈需核对的法源，而不是编造业务事实缺口。未添加HR、人数门槛或案例ID的生产规则。

历史引用的直接原因是`filter_hits_as_of`只检查`effective_date`，没有过滤未来`publish_date`；指南、清单、问答通常没有生效日期，因而进入真实返回的证据。现已同时核对发布时间，相邻证据扩展后再次过滤，最终报告也按最终工作事实的审查时点复查。实际返回过且该时点有效的证据继续可引用，未展示的候选不再通过报告组装进入证据集。六个原checkpoint离线回放共排除56条未来证据，剩余未来证据为0，证据保存在`data/review_runs/agent_fix_diagnostics_20261010/temporal_replay.json`；这只是过滤回放，不是重新生成法律报告。

Judge原评分对遗漏例外标`minor_issue`且仍PASS，原因是缺少明确违规记录和评分一致性约束。现在增加`rubric_violations`及相应失败分类，并要求明确违反已有约束时判失败。程序仅保证已识别的违规或失败维度不能被总评PASS覆盖，不承担法律识别，也不分析自由文本理由来强制改分。新增评分协议单列为v2，原始评分保持不变。
