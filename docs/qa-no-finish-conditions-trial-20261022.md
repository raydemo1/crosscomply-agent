# 删除 QA finish.conditions 的候选实验与复核

## 结论

候选有局部向好信号，但当前实验不足以采用。保留生产字段、DeepSeek / low及当前提示。尤其不能把最后一题未完成当成候选在生产中的交付退步：该题被冻结证据夹具和人为请求上限限制。

## 试验与结果

评测进程从实际 execute_qa 入口执行；同一批既有证据从第一轮预载。基线与候选首次请求逐一核对，除finish.conditions及其相关契约说明外，其他工具和非system消息一致。没有Judge或答案重写，没有修改生产源码。

原候选残留了evidence_gaps说明中对conditions的引用，已停止并保留，不纳入比较。清理完整后的候选运行八题各一次，基线成功答案复用；中断基线未补抽。最终双方各七题完成，六道可以完整配对：目标错误3→1。题目为未经专业审定的开发候选，不是法律准确率。

## 为什么候选最后一题没有交付

用户原问题是“海外 HR 系统同步员工通讯录，应该准备哪类文件和备案？”更正集体合同为未知后，模型需要解释无法豁免分支下的备案材料。

1. 候选首先请求《个人信息出境标准合同办法》第三、四、七、九条。冻结证据里只保留了第五、六、八条，四个精读请求全为空。
2. 再搜索只能得到原来的同一集合。来源级读取仍只返回这三条，却输出truncated=false、没有续页，容易被理解成已经读完整个来源；模拟联网固定返回空。
3. 随后模型试读邻近片段，程序拒绝重复读取。下次模型请求被四请求诊断上限拦截，没有完成最终答复。
4. 免费核查实际本地语料发现，第三、四、七、九条全部存在。第七条正是备案期限与材料条款，属于问题所需原文。它不是语料没有，而是未进入旧冻结子集。

因此，诊断夹具提供不了模型合理请求的证据，又没有忠实呈现来源读取边界，这是此次未交付的重要原因。真实工具链可读取这些条文，本次没有验证其完整运行。不能直接归因于字段删除，也不能据此扩大生产预算。

基线选择在同一证据缺口下作答，但仍将集体合同“无法确认”并入不成立，并将影响评估未知状态写成“最需要补做”。成功返回答案不意味着更正确。

## 为什么局部改善还不能算稳定收益

- HR未知题基线使用finish.conditions，候选未使用finish便作答，保留了分支，符合减少清单牵引的假设，但尚不能排除不同调查路径和采样。
- 定位参考题两版都直接作答，均未调用finish。因此改善不能归因于“删除已生成的conditions清单”；可能与工具Schema提示作用或采样有关，尚未隔离。
- 人数题候选不经工具直接作答仍推定规模，说明该错误不依赖conditions链路。它更接近当前输入下的事实理解与推断问题，但不据此宣布模型能力上限。

## 后续方法修正

下一轮应让两版使用同一份冻结的完整语料和真实读取/导航契约。不能把旧题实际取得的局部片段当成可继续调查的完整语料，也不能用固定空联网伪装真实搜索。冻结证据只能用于固定证据推理比较，不能据其受限调查的未完成率评估生产交付能力。

执行预算保持生产原值；费用上限用于停止后续任务，执行失败和缺少原文分别记录。只有在这个条件下复现内容收益，再过独立场景，才考虑采用候选。不再围绕人数题加提示。本次未追加付费诊断。
