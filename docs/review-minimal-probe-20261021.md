## 问题在哪里首次可见

第二次模型响应的 record_facts 入参已经包含：

1. 12 万/120 万哪份记录正确。
2. 数据是否确实不含敏感个人信息、未被告知或公布为重要数据。
3. 本年度后续出境是否预计使累计人数达到或超过 100 万人。

第三次请求的工具结果将同一清单放在 state.facts.missing_information 中返回，同时 observation 为 recorded=true。最终 finish 草稿又沿用了它们。问题不是独立核验器新增的，也不是程序自动拼出的事实问题。

实际取得的 2025 年 10 月政策问答第 7 问，讨论持续出境时是否需要多次备案。其合理预测表述有“仅涉及同一境外接收方”等条件，随后另说实际累计达到申报条件时如何办理。完整问题、条件和答复均进入第二次模型请求，不存在只传“预计”两个字或剪掉该问题前提的情况。模型将这个办理场景中的预测扩大成当前二选一路径判断的必补事实。

原文、既有消息和前轮 reasoning_content 都保留在原生对话中。这支持排除“前轮消息或原文完全没送入模型”的解释，不能证明模型正确使用了所有上下文。

另有需要复核的表述：草稿把“达到评估门槛却采用合同”直接接成“数量拆分”，没有指出案例中具体实施数量拆分的事实。本次只以前述待补清单问题触发停止，不扩展模型测试验证这一点。

## 为什么 record_facts 容易承接并放大问题

### 已证实的工具与状态契约

- 工具要求更新完整工作事实投影。facts 接受整个 ReviewFacts，而不是只接收外部材料观察。
- ReviewFacts 中同时包含业务值和 missing_information；后者只是字符串列表，没有逐项来源、影响哪个当前判断或仅为后续建议的身份。
- 运行代码先登记 material_facts，再直接执行 state.facts = decision.facts，返回 recorded=true。此处检查格式与来源容器，不检查某个问题是否确实阻塞当前目标。
- material_facts 与整份 facts 是两个独立参数。此次新增问题没有进入材料观察账本，但仍通过 facts 写入并被后续上下文回传。
- 事实账本保留 extracted 身份，没有把未来预测登记为 confirmed。程序也没有更新冻结填报。问题是研究判断与工作事实缺口共用了同一个字段，不能描述成程序已经完成了事实核验。

直接用真实入参执行一次本地 Schema 检查确认其合法；该检查没有模型调用，记录为 record-facts-contract-audit.json。

### 证据能支持到哪里

当前轨迹证实错误先进入工具参数、再被状态保存和报告沿用。“状态回传让模型更坚持原先判断”是合理机制假设，尚未做去掉这次写入的同输入对照；不能直接宣称 record_facts 是所有错误的根因，或删除它就能答对。

本案还把“材料已陈述、未经独立核验”处理成了“本轮尚缺的前提”。前者可在保留来源身份的条件下用于条件性回答，不能不分情形全部重新询问。正式审查仍需保留具体冲突、事实确认和审批要求。

## 与旧轨迹的关系

- 六题版人数题：首稿与最终清单均要求确认全年预计是否达到 100 万人。
- 上一轮整组调优版：首稿和最终稿没有这项未来预测问题，但又新增了自贸区事实要求。
- 当前最小工程版：首稿再次出现未来预测要求，同时重问数据性质；未取得核验结论。

说明这类错误早已存在，工程契约修复没有自动消除它。三次完整调查不是提示单变量对照，不能单独证明 C1 的收益或撤下 C1 导致本轮错误。

## 后续设计建议，尚未实施

优先收窄 record_facts 的写入职责，使材料观察与 Agent 的疑问分开。材料观察保留来源身份；模型关于未知、需调查、后续监测的判断不要作为事实的一部分保存。需要补哪些业务事实仍在当前目标下决定，不因保存成功就被视为已经确定需要补充。

不增加新的总结阶段，不清空原生对话，不增加记录后独立语义核验模型，也不写“未来/100 万”等专用字符串过滤。字段契约只能减少错误持久化和身份混用；问题是否必要，仍需要 Agent 及既有核验正确理解任务与原文。

本轮到此停止。当前问题更适合先评估 Agent 的任务边界及记录工具职责；尚无本轮证据支持恢复 C2 逐项覆盖或调整核验器行为。
