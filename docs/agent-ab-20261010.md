# 2026-10-10 Agent 推理引导 A/B

比较A（2026-10-10修复后的生产方案）与B（主动调查反证及有限对照证据）的表现。B只由评测脚本在单次运行范围内注入，未替换生产Agent；两组使用同一生产代码、模型、语料、预算和v2评测judge。每组6案、每案一次，逐案交错运行，3案A先、3案B先；不能据此做统计显著性或法律可靠率结论。

## 预先固定的比较范围

| 案例 | 比较重点 |
| --- | --- |
| HR已确认免予正例 | 机制选择、非同意依据、人数变化后仍成立的例外 |
| HR集体合同未知 | 不将未知认定为不成立；条件成立分支的剩余义务 |
| 境外来源回传 | 第四条例外、引入重要数据后不能仍套普通人数路径 |
| 个人酒店预订 | 第五条第一项、不添加不存在的敏感信息排除条件 |
| 小量敏感信息 | 路径应为标准合同或认证，检验过度拒答或错误免予 |
| HR人数对照 | 只把12万人改为120万人，其他确认事实与rubric不变，检验例外关系是否保持 |

前五案来自原候选集；人数对照是AI核对的合成实验输入，不加入已审校Golden候选清单，不称为独立专家留出。

## 实验干预与判读

A保留现有提示和仅被引法条的verifier视野。B增加围绕关键断言调查相反依据的通用目标，并给同一次verifier最多8条、正文合计最多12000字符的未引用正式证据作为对照。资料只来自该运行实际返回的证据，不查询完整语料，不自动成为报告引用，不规定检索阅读顺序。优先同已引用来源，再按原检索分数选择，完整条文不截断。这是两项干预的组合对比，不能分离各自贡献。

两组保留同一独立评测judge协议；judge不接收实验标签或生产语义判词。原始评分与逐份AI离线复核分开报告，重点检查主机制、附加义务、后续条件分支、无必要的拒答、预算耗尽、提交重试及耗时。明确区分法律问题、评分遗漏、输入歧义与运行故障。总评PASS不自动证明这些细项正确。

脚本为`scripts/run_agent_ab.py`，`--dry-run`验证输入而不调用模型。真实运行逐案保存输入、事件、checkpoint、最终结果、judge输入及`verifier_inputs.jsonl`，并冻结提示、完整案例、运行顺序、配置、代码与语料散列。生产节点的实际模型调用会收费；未采集到账单或token成本时不估算金额。

本次在首次实跑前固定方案。出现确定认证、余额或限流阻断后停止新的模型调用；不因分数不理想改题或在本轮调整提示。最终只按实测证据选择是否采用B，不预设B优于A。

## 报告复核：主结论之外的问题

以下是AI根据最终报告、调用记录及官方法条进行的离线复核，不是法律专家审定。原始评分保持不变；不按关键字或案例ID强制改分。明确的既有rubric违反与新增报告断言的问题分开记录。

| 案例 | A | B |
| --- | --- | --- |
| HR已确认免予 | 主免予正确；仍要求补齐员工单独同意，违反原rubric | 同样遗漏非同意依据；未因反证提示解决 |
| HR集体合同未知 | 正确保留未知和条件分支；仍一概要求单独同意 | 同样的问题；verifier已经看到第十三条却放过错误建议 |
| 境外来源回传 | 主免予正确，变化后泛称重新判断 | 主免予正确；把引入重要数据也写成重新按数量门槛判断 |
| 个人酒店预订 | 主免予正确；仍一概要求单独同意，把未达安全评估人数门槛列作同时成立的必要前提 | 同意义务改善为按处理依据判断；但新增非CIIO前提，并建议接近人数门槛即切换安全评估 |
| 小量敏感信息 | 正确选择标准合同或认证 | 同样正确，无过度拒答 |
| HR人数仅改至120万 | 仍免予；核验反馈后正确处理第十三条；最终却称以后加入敏感信息会使HR免予失效 | 仍免予，并正确区分非同意依据；敏感信息变化只提示重新评估，未断言自动失效 |

HR正例、酒店案的一概要求单独同意，直接违反冻结rubric。HR未知案的条件分支同意问题、回传案重要数据分支、酒店案额外前提及人数建议、人数对照A的敏感信息分支，是离线复核发现的附加法律断言问题；没有在本轮改题补rubric来制造失败。

法律依据分别是[《个人信息保护法》第十三条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)对合同履行及合法HR必要处理的非同意依据，以及[2024规定第五条、第七条和第八条](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm)的独立免予条件和衔接关系。第五条的合同履行、HR免予不以非敏感信息或普通人数低于100万为条件；第七条保留第三至六条例外的优先适用。重要数据是独立的机制触发因素，不能仅套普通人数门槛。2024历史案例的判断使用当时已有效法条，没有用2026问答替代历史依据。

两组的回传及酒店历史案例共4份最终报告，引用中的未来发布时间或生效日期均为0。该结果支持日期过滤修复有效，但不证明法律推理问题已经修好。

## 为什么增加反证仍未稳定改善

生产Agent已有自主`search_evidence`和`read_evidence`能力，检索底层已有关键词与向量融合。HR正例两组均未返回个保法第十三条；B多次主动搜索仍围绕第三十九条、告知、单独同意和第五十五条。没有提出“本案是否存在不需同意的处理依据”这一具体争点，对照视野只能扩大已经拿到的证据，不能补出未检索到的例外。

但不能把所有失败归为召回不足。B的HR未知案已返回第十三条，并把完整条文放入8条对照证据之一。Verifier仍称报告未一概扩张义务，并认为第十三条不足以推翻结论。主条件判断确实正确，但其建议同时写着“无论是否适用免予机制”均需单独同意；校验没有处理条件成立分支的非同意依据。这里直接体现了适用关系推理和整份报告核查不足。

A的人数对照在120万人时主动检索到了第十三条，verifier指出报告一面承认非同意依据、一面要求单独同意的矛盾，Agent随后修正。B在同一对照中一次核验就正确说明人数不改变已成立免予。这证明两套方案都有正确完成的能力，也显示B有局部收益；不能反过来声称A、B在原HR案上的旧错误已经消失。

## 选择与后续范围

暂时保留A生产方案，B留在隔离实验脚本。当前证据不支持将B整体替换进生产，也不支持宣布A可靠：B在酒店的同意义务和HR人数对照上有改善，但HR两案仍有问题，另有条件变化分支错误；A的目标问题也没有稳定消除。此轮不扩大付费评测、不重复成功项寻求更好分数。

后续更有价值的方向，是围绕Agent准备新增的具体义务或条件提出法律争点，由Agent自主检索适用范围、例外及相反依据，再让verifier处理这些依据与该断言的关系。反馈应说明需核查或修正的断言及原因，保留Agent选择查询、阅读和修订的权利；不固定HR条号，不规定执行顺序，不按人数映射路径。评分器也需先用本轮历史输出离线校准，不能继续把其PASS当作修复证据。上述方向未在本轮实现或付费验证。

原始证据位于`data/review_runs/agent_ab_20261010/`，补跑位于`data/review_runs/agent_ab_20261010_continuation/`。补跑目录的`comparison.json`合并12个最终结果，`offline_assessment.json`单独保存复核和缺陷分类；两个原始`summary.json`及旧HTTP 402记录未覆盖。两段运行的生产文件散列均无变化。

实验脚本验证：全量pytest 620通过，Ruff及diff-check通过。上述真实模型结果与无模型成本测试分别记录，B未成为生产改动。


## Flash 思考强度与核验协议诊断

在原配对结果之后，按用户授权只重放冻结的 verifier 输入，没有重跑完整 Agent，也没有调用 Pro。共 7 次 Flash 请求，6 次完整输出、1 次因当时的输出上限截断。前 4 次在移除上限指令之前发送，后三次不设置 `max_tokens`；生产客户端与当前诊断脚本均不设置输出 token 上限。供应商自身默认输出长度仍然生效。

| 输入与干预 | 结果 | 判读 |
| --- | --- | --- |
| 已确认 HR 报告，补充完整第十三条，none | supported | 仍漏过一概要求单独同意的问题 |
| 同上，low，原 4096 上限 | length，无最终答案 | 运行截断，不计作法律判断失败 |
| 同上，low，原 16384 上限 | uncertain | 识别同意义务适用关系及额外门槛问题 |
| HR 集体合同未知，原 B 输入，low | supported | 识别保存期限缺依据及需核对同意关系，仍认为主路径正确而放行 |
| 同上，逐报告片段协议，low | 模型总评 supported；聚合后 uncertain | 仅保存期限片段标 uncertain；同意义务仍漏判 |
| 120 万人数正确对照，逐报告片段协议，low | uncertain | 对已有第十三条非同意依据的判断产生误拦 |
| HR 集体合同未知，逐报告片段协议，high | uncertain | 仍只指出保存期限缺依据，未识别目标同意问题 |

已确认 HR 输入中额外提供的第十三条来自语料，是诊断时人工选择给 verifier 的依据，不代表生产 Agent 已经成功检索到它。其余输入保留原报告、冻结事实、材料和 B 对照法源。逐报告片段实验增加完整覆盖的 `report_checks` 与具体 `research_questions`，没有改案例、rubric 或法源正文。low/high 疑难对照使用完全相同的消息和输出协议，各只有一次完整样本；不能据此推算准确率或宣布 high 普遍无效。

正确对照的误拦是 AI 根据[《个人信息保护法》第十三条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)第二款及报告已明确的必要性条件作出的复核判断，不是法律专家审定。逐片段 low 在错误报告中接受“一律取得单独同意”，却在正确对照中质疑“符合第十三条的处理不需同意”，表明协议仍不能稳定处理同一法律关系。收紧总评确实能阻止模型已经承认的局部问题被放行，但不能替模型发现遗漏，也不能纠正误判。

因此最终只采用两项生产改动：主 Agent/案件追问和独立语义核验分别默认 low，可独立选择 none/low/high/max；现有 `claim_checks` 中 unsupported/uncertain 自动收紧相矛盾的总评，并把具体原因返回原 Agent。其余格式化节点与自动 judge 保持全局默认 none。没有自动升级 high，没有新增法律路径规则、按案例 ID 特判或自主 verifier 检索循环。逐报告片段协议保留在 `scripts/run_grounding_probe.py`，不作为生产拦截条件。生产 prompt 与输出字段保持原有协议。

[DeepSeek 官方思考文档](https://api-docs.deepseek.com/guides/thinking_mode/)列出的实际强度为 low/high/max，none 关闭；medium 映射到 high，项目不再提供单独的 medium 选项。主 Agent、verifier、案件追问已使用 JSON 输出，能启用思考；受限制的是当前 strict_tool 分支强制指定工具的 tool_choice，并非严格 schema 本身。

7 次诊断按实际 usage 和[官方峰时单价](https://api-docs.deepseek.com/quick_start/pricing/)估算合计约 USD 0.1062，最后 3 次约 USD 0.0673；这不是账单金额，未按实际分时计费确认。逐片段疑难 low/high 分别耗时 76.05/84.39 秒，生成 17536/20001 tokens（含思考）；high 本次更贵，目标问题未改善。只保留 usage 中的思考 token 数，不依赖或展示内部思考文本。

证据位于 `data/review_runs/grounding_probe_20261010/`，包括每次请求/响应、usage、三个阶段 manifest、冻结输入和独立复核。旧截断和原始 supported 输出均保留。最终生产主 Agent 默认 low 尚未跑完整真实基线，这次核验重放不能证明原有全部 bad cases 已经修复。下一轮正式评测的 manifest 按 Agent、verifier、judge 分开记录实际思考配置。

最终改动验证：全量 pytest 632 通过，全仓 Ruff 与 diff-check 通过；A/B 与基线脚本 dry-run 均为零模型调用。没有改 Golden 案例或 rubric。

## 提示简化与供应商推理文本诊断

随后按用户授权继续小范围验证，检查约束过多是否使 verifier 丢失核验重点，并保存供应商返回的 `reasoning_content`。新增 12 次 Flash low 请求，不设置 token 上限；全部是冻结报告的 verifier 重放，未重跑完整 Agent，未修改生产提示、Golden 案例、rubric 或语料。该字段是供应商输出的诊断文本，不保证包含完整内部计算，也不能单凭它认定根因。此前 7 次诊断未保存该字段，无法事后恢复。

第一阶段用同样的事实、材料、报告、法源和生产 `SemanticVerdict` schema，比较原提示（2377 字符）与简短提示（734 字符）。两份错误 HR 报告和一份正确的 HR 人数对照各跑两个版本，顺序交错。第二至四阶段根据已观察到的输出调整实验，是自适应诊断，不是预先固定的独立留出评测。

| --- | --- | --- | --- |
| 原提示与简短提示 | 6 | 原提示漏过已确认 HR 错误、识别集体合同未知报告中的同意问题、接受正确对照；简短提示漏过两份错误报告，并把正确非同意依据判为 unsupported | 不采用简短提示 |

“识别错误”要求理由具体覆盖同意义务的过度适用，不能仅因无关的保存期限或人数引用问题未通过就计为目标改善；“正确对照”要求不误拦已给出的非同意依据。上述判读仍为 AI 根据报告及官方法源作出的离线复核，不是法律专家审定，不将这些样本换算为 Golden 准确率。原始响应保持不变。

推理文本显示：模型读到了第十三条的非同意规定，却多次引入输入没有提供的“学界争议”“特别规定优先”等解释，在不同结论之间反复改变判断；它还反复讨论主机制正确是否足够通过，把义务适用与手续是否完成混在一起。部分最终响应也将法律依据缺口写进 `missing_facts`，虽然 schema 对应的是业务事实。这些现象支持继续排查适用关系和核验目标理解，不能证明单纯扩大召回或缩短提示就能解决。标出焦点时的推理还受到实验指引影响，不能当作独立验证。

| [FACTS Grounding，2025](https://arxiv.org/html/2501.03200v1) | 在人工标注的保留集上选择 judge 提示；同时检查 grounding 和是否实质回答问题 | 借鉴校准与误报/漏报分析，不复制三个昂贵 judge。该数据构造明确排除需要专家知识、数学/逻辑推理的任务，不把其分数迁移成法律判断保证 |
| [Large Language Models Cannot Self-Correct Reasoning Yet，ICLR 2024](https://arxiv.org/abs/2310.01798) | 在该文测试设置中，无外部反馈的自纠错可能无效甚至退步 | 更长自检提示、同模型投票和提高 effort 都只作为待验证干预，不能替代真实来源与独立判读 |

本地核对发现两处结构限制：`SemanticVerdict` 强制覆盖全部 claim_index，但其他报告字段只有总体理由，没有可验证的错误位置；`SemanticGroundingVerifier.__call__` 的正式法源输入按 draft.claims 引用过滤，而辅助解释输入保留未引用资料。保存的 unknown_5/call_026 输入仅含《促进和规范数据跨境流动规定》第五、七、十条；研究实际取得的个保法第三十九条未进入 verifier。unknown_4 的错误在已有第五、七条输入下仍漏检，说明来源过滤不是所有失败的解释。

下一版收敛为三项可单独对照的改动：

1. 独立调查采用由模型生成的开放问题，保留题设所有关键条件与未知状态，但不把待核对结论作为回答锚点；调查完成后才与原断言比较。研究仍需实际搜索/阅读，不用参数知识代替证据。
2. 在现有 verifier 中增加可定位的报告问题反馈：字段或数组索引、原句、unsupported/uncertain、对应证据或缺失前提。区分业务事实缺口与法律依据缺口。程序只校验原句位置、证据ID和状态聚合；不判法律适用、不按关键词选择错误。检查原报告各栏目是否含断言，不能把无引用建议视为无须检查，也不能由覆盖记录推断语义检查正确。
3. 核对 verifier 的来源边界：用相同冻结输入比较“仅被引用的正式法源”与“本次已取得且去重的正式法源”，记录新增噪声、漏报、误报及输入成本；完整条件与例外原文不得被摘要替代。尚未取得的法源应反馈给主 Agent 调查，不由 verifier 凭空补齐，也不直接将所有检索历史塞入每次检查。

修正反馈交回主 Agent 后，由主 Agent 更新摘要、正文、建议、claims 与问题记录，原 verifier 复核新的完整草稿；在初次对照中不额外叠加一个生产检查节点。目标覆盖与 grounding 分开判读：删除用户明确要求回答的问题或只写“依法办理”不算修正成功，目标范围外的附加义务则可合理删除，不能为提高覆盖而扩张审查。

先使用已有错误报告、正确条件性分支和合理暂行准备建议做冻结输入对照；另保留未用于修改提示的输入进行验证，开发阶段标签不自动成为人工审定 Golden。重点记录：错误漏过、正确判断被拒、错误位置准确性、修正后的残留/新增错误、目标问题覆盖、调用成本；暂不报告小样本准确率。只有冻结对照有明确收益且不过度追问/拒绝正确报告，才补少量完整流程重复，仍使用 Flash，不采用默认生产研究 hook 或多模型投票。
