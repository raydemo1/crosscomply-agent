# 问答输入修复与受控对照

2026-10-20。本轮修复初始材料上下文、增加有原句约束的范围粗筛，并修复试验暴露的数据库读事务问题。完成两道HR题的各一次实际模型执行，以及四次同原生对话的小探针；预定的范围外资料探针因Agent未提供排除参数而跳过，没有替换探针或补跑挑结果。

结论：两题都正常交付，历史时点提取有改善；耗时一降一升，答案质量仍未稳定改善。已确认一处错误的相关例外原文在首轮检索中就已提供，但未进入最终引用选择，也未体现在正文中。不能把问题全部归因于检索缺资料、最终模式切换或Schema大小。

## 代码修改及其验证边界

1. 初始上下文直接提供当前选中附件的首个原文窗口，沿用12000字符页长及原始版本、偏移；提供剩余材料续读参数，不生成摘要，不强制先执行某个工具。历史复用也识别这个已提供窗口，未选材料和新旧版本不混用。先前初次请求只有附件名称和长度，Agent可以在看不到业务限制时并行搜索。
2. 搜索线索增加`excluded_source_scopes`，包含范围名称、别名和支持该排除的用户原句；原句必须来自用户问题、历史用户陈述或本轮选中的材料，否则返回工具参数反馈。程序只对专项来源的标题、适用主体匹配，不按正文观点删资料，全国一般法律及用户点名来源保留。未提供和空列表分别表示保留、清除已有排除，不引入完整事实表、核验模型或审查关卡。
3. 向量检索的SELECT使用独立事务上下文，成功结束或异常时释放事务，不再在模型思考期间维持`idle in transaction`。

前两项同时进入本次实际运行，且模型采样非确定；不能把某项运行变化精确归功于其中一个。两题均未填写排除字段，因此**没有自动范围粗筛已经改善Agent输出的真实证据**。

实际工具定义8015字符，没有完整ReviewFacts定义；比上一轮增加876字符。首请求两题分别5051、5100 token，上轮为4361、4364。新增原始业务输入和轻量范围结构有固定输入成本，不能只报后续总量下降。

集体合同未知题的首个搜索结果包含2026年7月政策问答片段`cac_data_export_policy_qna_2026_07:2961b0508c679061a2f863ab`。它既说明一般告知同意规则，也说明第十三条第一款第二至七项情形的同意例外，文本完整提供，没有被粗筛或摘要截掉。

Agent最终选择了第三十九条等一般条款，没有登记这个问答片段，正文也没有解释其例外；随后两次固定最终对话的`none/auto`答复仍然只作一般单独同意要求。这条证据将问题缩小到**调查判断、证据选择及规则衔接没有落实**，而不是这一例外从未检索到。记录见`exception_coverage_audit.json`。不能从中反推模型私有思考过程，或把原句锚定存在当成法律专家验收。

其他残留：未知题仍把已说明的HR必要性扩成待确认具体字段，并出现“经确认可采用单一方式”这一未取得直接解释的分支；已确认题又把单独同意列成必备准备事项。更快的未知题并未保留上轮对同意例外的完整说明，已确认题也没有因为正常交付而达到质量验收。

## 同一原生对话的探针

探针保留同一份系统提示、工具定义、用户输入、原生assistant思考字段、工具调用及结果编号，不重写法律答案。只存消息哈希和思考长度，未保存或分析私有思考正文。

### 重复同输入与增加同源资料

参考点为未知题首次搜索与网页发现之后、下一次调查之前。参考请求与重复探针输入均为24948 token；两者都选择读取，但条款选择不同：参考读取第五、七条，重复探针读取第五、七、十条。思考输出从530变成226 token。即使完全相同输入，模型行为也有波动。

增加10个同来源池片段后，输入变为28101 token，下一步仍为读取，思考440 token。它位于两个相同输入样本的波动范围内；这次小对照不能证明“资料多一点必然显著拉长思考”。同源不代表每个新增片段都相关，探针只测试下一决策敏感性，不能替代完整运行的法律质量评估。

### 范围外资料探针未形成

Agent未填写范围排除，所以没有可据实际参数分类的排除集合；该探针按预定规则跳过，不能声称完成了无关资料的模型因果对照。

另用相同实际查询及检索线索，手动传入来自用户“不在自贸区”原句的范围词，独立验证了工具。原结果中的北京地方清单被移除，全国跨境规定和个保法保留；结果数均为29，因为现有top_k会补入其他来源。因此，粗筛可以改变来源组成，但不保证输入片段数减少。它不等同于Agent自主使用了此功能，也不证明相关性或答案质量提高。

## 数据库阻塞：与模型耗时分开

为保存首题工具供后续探针使用，脚本保留了首题连接。实际SELECT在非自动提交连接上留下未结束事务，第二连接初始化时的`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`被它阻塞。保存的`pg_stat_activity`显示等待关系锁及对应阻塞PID；第二题当时尚未发出任何模型请求。

只取消了已核实的第二个等待会话，保留原失败记录和252.3秒基础设施等待。首题与四个探针正常完成，原批次后端源码及语料散列不变。修复事务后，保持首个读连接打开，验证事务状态为IDLE，第二连接结构检查16毫秒完成，未触发1500毫秒锁超时。

第二题随后才第一次进入模型执行，结果保存在`after_transaction_fix/`，没有重跑已生成的答复，也未用72.3秒覆盖原等待记录。该次源代码仅增加事务释放修复，另有独立源码散列及未变化检查。
