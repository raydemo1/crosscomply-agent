# 关键原文为何没有进入问答上下文

2026-10-20。承接原文Oracle，检查两次真实运行的查询、返回正文、导航、精读及引用选择，并复放其查询的当前真实ES/pgvector检索。没有调用回答模型、修改生产代码、重新建库或执行Agent评测。

**针对已确认HR条件题的同意例外遗漏，当前应优先定位为检索供给及结果裁剪问题。关键原文在库中，部分已被底层召回，却没有通过工具成为模型可见输入。不能将这种缺原文的表现直接归为模型能力上限。** 另一题还有“已经给出例外原文但最终未使用”的独立问题，不能都合并成底层未召回。

| 集体合同未知：2026年7月问答第1问 | **是，包含末尾同意例外** | 不需要，已有正文 | 无另行精读 | **否** |

这里“候选导航”指实际工具返回的`keyword_candidates`，不是后台候选池。后台召回但没有放进正文或导航的资料，模型无法据此决定续读。

未知题只精读跨境流动规定第五、七条；已确认题只补读个保法第十七、二十一条。没有第二次法源搜索补齐第十三条。未使用的搜索、读取预算不代表模型取得了缺失条文。

当前ES与pgvector均存在第13条及该问答，`retrieval_enabled=true`，原文与本地语料一致。因此目前不是缺文件、解析掉了例外、未建立向量记录或资料被停用。

## 复放揭示的具体截断位置

当前配置每个查询分别取关键词50条、向量50条；融合后再截为50条；按来源折叠并且每个查询最多保留10个来源，随后跨查询合并最多10个来源。每来源通常带2个支持片段，保留各查询代表片段作为锚点；前5个来源另作相邻片段扩展。导航则只检查关键词前10条，每查询最多补4个未返回位置。

下列排名为**本次当前后端复放**的一基排名，不是原始运行已保存的底层排名。原运行未存关键词/向量全候选，不能倒填成历史原始日志。

### 未知题：第13条在融合截断处丢失

实际HR查询是：

> 促进和规范数据跨境流动规定 跨境人力资源管理 劳动规章制度 集体合同 免予

第13条在关键词召回中排第32，向量前50中没有。对这两路结果计算完整RRF后，它排第56，超过融合候选50条上限。因此没有进入后续来源包。关键词导航又只看前10，不能把这个第32名作为续读线索交给模型。

本题的同意查询为：

> 个人信息保护法 第三十九条 单独同意 向境外提供

7月问答关键词第7、向量第5，融合第2，成功返回完整正文。它在原运行确实进入上下文，不能继续说这部分是检索未召回；后续finish只选8个依据而没有该问答，最终回答也未使用其例外。

本题复放返回29个片段，**编号及顺序与原搜索完全一致**。原运行再精读2条形成最后31片段。它支持本次定位具有复现性，但不把复放排名冒充旧请求日志。

### 已确认题：问答在来源选择处丢失

实际同意查询是：

> 个人信息保护法 第三十八条 第三十九条 向境外提供个人信息 安全评估 标准合同 认证 单独同意

7月问答关键词排名**第13**，向量前50未命中；单独扩大向量窗口的诊断中排名第67。在原候选窗口下，它融合后排**第31**，仍然进入50条候选；但按来源折叠后，其来源排**第13**，每查询最多取10个来源，因而被丢弃。另两个查询也没有把这个来源带回来。

关键词导航只看前10，问答的第13名又被挡住。因此程序内部候选有它，模型既没见到正文，也没见到其导航位置。

同一来源排名中排在它前面的包括澳门标准合同及关键信息基础设施保护条例等。实际关键词前20还包含其他法律的第三十八、三十九条，说明法律名称和条号并未约束目标文档。它们不是必须同时满足的结构化检索条件，只是多字段全文检索的普通词项。

该题第13条更早就缺失：三条实际查询分别聚焦38/39条及出境机制、跨境HR免予、55/56条及影响评估，**没有围绕处理合法性基础、无需同意或第13条发起搜索**。第13条在这三组查询各自的关键词和向量前200中均没有出现，也没有后续按条号精读。不能假定仅靠一般“跨境HR”和机制词一定能检出处理合法性基础。

本题当前复放仍返回32片段，关键两个原文仍没有正文或导航，但有3个末端片段替换：原网络数据安全管理条例的片段换成标准合同范本片段。因此**本题没有实现全部返回编号完全复现**。源代码与旧运行清单逐文件哈希一致，但旧底层候选、查询向量及服务端状态未完整存档，不能确定该差异来自哪一项。本次的“第31/来源第13”是可复核的当前机制证据，旧运行只能直接证明最后的不可见状态。

## 为什么这些规则没有自动补回来

1. **查询覆盖不完整。** 已确认题首个检索说明已经将“单独同意”列为仍须履行的义务，搜索也围绕该一般要求展开，没有调查其处理合法性基础。这里是调查决策与检索输入之间的缺口；不能断言私有思考过程，但对外生成的查询与说明可以直接核对。
2. **融合并非保留两路所有相关结果。** 仅被关键词命中的第13条会在RRF中让位于两路共同命中的片段；这次实际从关键词第32变为融合第56，并在50处截断。
3. **来源多样性不等于关键规则覆盖。** 新来源数量有限，已被召回的解释问答可以被来源前10名淘汰，未必因为它的内容对该问题没有价值。这里没有开启额外模型重排，`rerank_mode=off`。
4. **导航不能兜住被裁剪的相关候选。** 只看关键词前10，与正文来源前10两道上限叠加，让“召回但未展示”变成模型完全不可知。
5. **相邻扩展不是法律关系扩展。** 第38/39条前后相邻条文不会扩到第13条。当前来源包也没有识别“合法性基础与同意要求”的关联规则，而是排名、来源及物理相邻关系。

精读工具可以按来源和条号读取第13条，并不要求它事先进入候选。但Agent必须自行识别应当再查合法性基础；现有查询、返回原文及导航没有保证这一点。不能把“工具理论上能读”当作“模型实际取得”。

## 修复方向及未证明的内容

应先修通用检索和工具输出，而不是为HR题再加固定结论禁令或强制必读第13条：

- 点名法律及条号时支持准确的文档内定位；同一查询的主题检索可保留，但不要让其他法律同条号挤占精确定位。
- 保留对单一路径高相关结果的覆盖，重新评估融合及来源上限；对有用但未入正文的候选提供少量原文预览和可续读位置，不能让导航也被同一个窄窗口完全挡住。不要把全部候选原文塞回上下文。
- 围绕实际返回原文中的交叉引用提供可定位关系，让一般规则、适用基础和例外都能被发现；保留原文及资格，不由程序生成标准答案。
- 检查finish引用登记对子集的限制如何影响已经给出的例外使用；已取得资料与最终实际展示来源可以分开，正文未使用的来源继续不展示给用户。

这些是根据当前断点提出的实施方向，本轮没有验证其生产修复收益。Oracle补齐一组关键原文后两次答对，证明当前输入不完整值得优先修；不能由此计算第13条单独的贡献，也不能抹掉未知题“原文已在上下文仍漏用”的事实。

诊断数据位于`data/review_runs/qa_oracle_retrieval_diagnosis_20261020/`：`summary.json`记录原文可见性与排名，`raw_candidates.json`保存每路原始50条，`raw_top200.json`保存扩大窗口的独立查询，`cutoff_analysis.json`保存离线融合及来源排名，`packet_stage.json`保存组包阶段输入。实际文件均以case_id为前缀；`cutoff_analysis.json`及`summary.json`为全批文件。源码哈希保持不变。
