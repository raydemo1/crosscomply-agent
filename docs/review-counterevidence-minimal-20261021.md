# 核验支持／限制依据的最小修复试验

2026-10-21。按用户要求先实施最小候选，再用固定输入检查。结果未达到采用条件，**本轮候选已撤销，没有保留无效生产改动**。此前的问题分类、原文上下文及SSE修复均保留。

## 候选及范围

只在核心核验与栏目核验中共用一段“支持依据／适用限制”契约，使用现有reason解释决定判断的原文与事实关系：

- claim正向支持须符合提交的引用关系，但其他已取得原文可用于反驳或限定该claim。
- “某规则未免除一类义务”不等于该义务自身的条件成立或例外已被排除。
- 不增加字段、模型阶段、强制定位、来源检索器、调查预算或报告生成改动。

固定HR完整复测的核心request4，保留全部63条资料、原始事实、材料和报告。三次逻辑调用，每次一次请求，没有重试，不跑完整Agent或Judge。正向控制仅人工修正报告中的同意条件及对应引用，原始事实和全部资料不变；不是Agent输出，不覆盖历史报告。

不能把前两组整体uncertain算成拦截成功：退回理由与本次要修的claim5无关。单次耗时不同也不能证明候选提速。

正确条件稿的返回意见明确区分“一般处理合法性基础的同意”和“跨境提供的单独同意”，认为第十三条例外不能直接排除第三十九条的跨境要求。因此这次错误不仅表现为没有提及例外，模型还显式选择了错误的条文衔接解释。

## 法律依据与上下文进一步核对

为避免将自身解读当作评测真值，另行核对官方资料。网信办[《数据出境安全管理政策法规问答（2026年7月）》第一问](https://www.cac.gov.cn/2026-07/24/c_1786638883119336.htm)直接解释：属于个保法第十三条第一款第二项至第七项的个人信息出境活动，可以不取得同意，仍须履行出境告知义务。该官方解释是在对照运行之外核对，没有加入三次模型测试输入。

同一问答已经存在于本地语料：

- chunk_id：`cac_data_export_policy_qna_2026_07:2961b0508c679061a2f863ab`
- citation_role：`interpretation_auxiliary`
- can_cite_clause：false，仍是解释资料，不能升级为正式法条。

检查原完整HR重跑的7次模型请求，该chunk均未出现；三轮核验仅收到第十三条本身及其他法规、解释资料，没有这条直接解释同意衔接的问答。原调查查询集中于HR免予条件、100万人门槛、HR处理合法性基础、集体合同生效程序，没有针对“跨境单独同意与非同意合法性基础如何衔接”补查。

因此，先前“不是检索问题”需要限定：**第十三条正式原文确实到位且未被截断，但不能据此断言消除这处歧义的解释证据也已齐全。** 目前同时存在模型的错误衔接判断，以及库内直接解释未进入本轮上下文的调查缺口。没有进行补入该解释后的模型测试，不能宣称取得它就必然修复，也不能据此认定模型上限。
