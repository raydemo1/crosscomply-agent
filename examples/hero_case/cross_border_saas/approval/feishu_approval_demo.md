# 飞书审批演示脚本

> 本脚本只描述演示步骤。审批实例 ID、用户、回调和签名均为示例，不得连接真实企业或复用为生产配置。飞书是最终审批权威；CrossComply 只创建实例、展示状态并幂等回写。

## 演示前准备

1. 使用飞书测试企业和专用测试审批定义，不使用生产审批模板；
2. 在 CrossComply 中确认案件绑定材料快照 `MS-CC-2026-DEMO-001-V2`；
3. 确认规则版本为 `cn-cross-border-main-path-2026.08-demo`；
4. 确认 `needs_info` 为空，整改清单已生成；
5. 演示环境通过环境变量或密钥管理服务加载凭据，任何密钥都不写入本目录。

## 通过分支

1. 审核人在 CrossComply 点击“创建飞书审批”；
2. 系统保存飞书返回的审批实例 ID，并将案件置为“待飞书审批”；
3. 在飞书测试企业中打开实例，核对案件编号、快照、候选路径和整改项；
4. 审批人选择“附条件通过”，意见填写：`完成 ACT-001/002/004/005/006/007 并上传证据后方可接入生产数据；ACT-003 按法定要求跟踪。`；
5. 飞书发送审批事件；CrossComply 验签后按事件 ID 幂等写入；
6. 刷新案件页，确认状态为“附条件通过”，展示审批人、审批时间、实例 ID 和决定文本；
7. 重放同一事件，确认不会新增第二条决定记录或逆转状态；
8. 导出报告并校验报告哈希。

## 拒绝分支

另建一个测试实例，审批人选择“拒绝”，理由填写：`供应商拒绝固化分处理者和删除证明机制。` 系统应回写“已退回”。后续补件必须创建新的审批轮次，不得在本地直接覆盖飞书终态。

## 网络失败分支

演示环境临时阻断回调处理或让测试处理器返回可重试错误：

1. 事件进入持久化重试队列并记录尝试次数；
2. 恢复网络后重试成功；
3. 同一飞书事件只产生一个审批结果；
4. 重试期间本地不得擅自显示为已通过。

## 讲解重点

- AI 审查完成不等于案件完成；
- 飞书决定是审批终态权威；
- 审批结果必须追溯到材料快照、规则版本、法源和整改项；
- 未知关键事实不能送审，不能靠提示词“猜一个答案”。
